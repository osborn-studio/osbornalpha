# osbornalpha feature map

The maintained list of user-facing features that `verify-osbornalpha` knows how to drive. Every file follows the same four sections: `Sub-features`, `How to get to it (user POV)`, `Driving it with <harness>`, `Gotchas`.
A proof that drives one entry point is incomplete when the file lists others.

| feature | file | journey (`scripts/drive.mjs`) | modes | needs internet |
|---|---|---|---|---|
| Landing page + zh/en i18n + design showcase | [landing-i18n.md](landing-i18n.md) | `landing` | guest, gate | no |
| Guest watchlist: search, add, persist, de-dup | [watchlist.md](watchlist.md) | `watchlist` | guest | yes (quotes) |
| Portfolio quote + K-line chart (+ Company Research unavailable state, research chain) | [stock-detail.md](stock-detail.md) | `stock` | guest | yes |
| Public market-data & search API | [market-data-api.md](market-data-api.md) | `quote-api` | guest, gate | yes |
| Auth gate (signed-out access control) + switched-off Feishu simulation import POST (#317) + signed-out refusals of admin-only `/admin/sources` (#331) and the Gildata industry vendor API / cron (#324/#332) | [auth-gate.md](auth-gate.md) | `auth-gate` | guest, gate | no |
| Macro Workbench guest view + four-tab row with the strategy flag off (#300) + static allocation template (hypothesis MarkCard) + research footer + research chain | [macro-workbench.md](macro-workbench.md) | `macro` | guest | no |
| Research hub `/intel` (five chain-ordered entry cards) + Topics switched-off state (`/intel/topics`, dossier, `/admin/topics`, `/api/topics`, `/api/admin/topics`) | [research-hub-topics.md](research-hub-topics.md) | `intel-hub` | guest (gate: login redirects in `auth-gate`) | no |

Not yet mapped (need real Supabase / credentials): sign-in and register, Macro data behind `/api/macro/*` (investment clock + breakdown, judgment slot, Fed liquidity / CN policy-rate series — see [macro-workbench.md](macro-workbench.md) Gotchas), Company Research at `/stock/[ticker]`, signed-in portfolio positions, `/research/*`, `/briefs`, `/settings`, `/copilot`, `/admin` (incl. `/admin/dq` data-quality dashboard — `src/app/(app)/admin/dq/`), Stripe billing, the Hermes / John Cameron CLI skills.

Not yet mapped (public read APIs that need a migrated Supabase with issuers/facts data — guest/gate modes have no anon DB, so these cannot be driven locally without credentials):
- Disclosure facts store (#102, CN path enabled in #104): `GET /api/facts/[ticker]` (`src/app/api/facts/[ticker]/route.ts`), `GET /api/facts/[ticker]/metrics` (`…/metrics/route.ts`), `GET /api/filings/[ticker]` (`src/app/api/filings/[ticker]/route.ts`). Spec: `docs/superpowers/specs/2026-11-04-data-foundation-2-disclosure-facts-design.md` §9; runbook: `docs/runbooks/data-foundation.md`. Without `NEXT_PUBLIC_SUPABASE_*` they 500 via `getAnonSupabase()`. #104 added real Tushare fixtures + §15 verification and turned CN sync on; it did **not** change these public read routes or make them driveable in guest/gate.
- Issuer resolve (data-foundation-1): `GET /api/entities/resolve` (`src/app/api/entities/resolve/route.ts`) — same anon Supabase + `issuers` / `issuer_securities` tables.
- Deprecated Tushare financials: `GET /api/financials/[ticker]` (`src/app/api/financials/[ticker]/route.ts`) needs `TUSHARE_TOKEN`; responses carry `Deprecation: true` and `Link` successor `/api/facts/{ticker}`. Prefer facts once seeded.
- Ops-only (not a user journey): `POST /api/cron/facts-sync` (`src/app/api/cron/facts-sync/route.ts`) — cron secret; `vercel.json` schedules US + CN (#104). CN is on by default, needs `TUSHARE_TOKEN` (503 `tushare_unconfigured` without it), kill-switched by `FACTS_CN_ENABLED=0`.
- Ops-only (not a user journey): `POST /api/cron/macro-sync` (FRED + CN official-HTTP collectors, #227/#228/#233) and the company evidence/digest CLI health work (#230: chunked evidence writes, freshness backlog tolerance) — no UI surface; covered by the repo's unit/integration tests, not by this skill.
- Research sections behind the research chain (chain itself is mapped in [macro-workbench.md](macro-workbench.md) / [stock-detail.md](stock-detail.md)): Industry research `/intel/industries` (+ `[scheme]/[code]`, `/constituents`; unified research UI since #261, read models in `src/lib/industry/`) and Company research `/intel/companies` read a migrated Supabase; guest renders their fail-closed/error states only. `INDUSTRY_E2E_FIXTURES=1` (`src/lib/industry/e2e-fixture.ts`) serves synthetic rows for the repo's Playwright suite — not product data, so it is not used here.
- Foreign broker research (#252, shared research UI #260): public `/intel/foreign-research` (+ `/[reportId]`, `/institutions/[institutionId]`) and `GET /api/broker-research/{reports,reports/[reportId],institutions,history,by-ticker/[ticker]}` are closed by default (public flag in broker-research settings, read over service-role Supabase; guest `GET /api/broker-research/reports` → 500 `internal` "reports unavailable"); the private library `/admin/broker-research/*` + `/api/admin/broker-research/*` is admin-only; crons `broker-research-outbox` / `broker-research-verify` and `macro-strategy-warm` are ops-only.
- Topic research with data (#270–#279; mapped only in its switched-off state in [research-hub-topics.md](research-hub-topics.md)): directory `/intel/topics` (`src/app/(app)/intel/topics/page.tsx`), dossier `/intel/topics/[slug]` + replay `/v/[n]` (`src/components/topics/dossier/`), research-chain step 05 / hub card 05 as links, admin editor `/admin/topics`, `/new`, `/[id]` and publish page `/[id]/publish` (`src/components/topics/admin/`), `GET /api/topics{,/[slug],/[slug]/versions,/[slug]/versions/[n],/[slug]/evidence/[ordinal]}` and `/api/admin/topics/*` — need `TOPICS_ENABLED=1`, a migrated Supabase with the topic tables, a session (admin for `/admin/*`), and `topic_settings.public_enabled` for non-admin readers. `TOPICS_E2E_FIXTURES=1` synthetic mode backs `e2e/topics*.spec.ts`; not product data, pinned off by `launch.sh`. Crons `topic-drift` / `topic-verify` are ops-only (cron secret).
- Company Research loaded page (`/stock/[ticker]` with an issuer: header action row, view tabs, phone layout — #264/#280): needs a migrated Supabase; see [stock-detail.md](stock-detail.md) Gotchas.
- Platform LLM base URL (`LLM_BASE_URL`, #255, `src/lib/llm/platform-base-url.ts`): operator config for LLM/copilot features, which need real LLM credentials.
- Topic summary (#287/#288): admin publish-page summary block (generate / approve / discard, frozen into the version) and its `topic_summary` usage feature (`/api/usage/today`, `src/components/UsageToday.tsx`, `src/lib/billing/{quota,cost-budget,metered-llm}.ts`) need topics on, an admin session, LLM credentials and a migrated DB; only the switched-off 404s are driven (see [research-hub-topics.md](research-hub-topics.md)). Copilot `topic_dossier` tool (#290, `src/lib/topics/copilot.ts`) is only registered with `TOPICS_ENABLED=1` and needs a working Copilot.
- Judgment card / settlement timeline copy (#286: translated status labels, abstain-reason and target-detail messages in `src/components/judgments/`, `src/components/industries/JudgmentArea.tsx`, `messages/*/judgments.json`, `messages/*/industries.json`) and the Company Research replay controls' 44px phone touch targets (#286, `src/components/company/ReplayBar.tsx`) render only with judgment / issuer data from a migrated Supabase.
- Macro explain validated-run refactor (#287, `src/lib/macro/strategy/{validated-run,explain-*}.ts`): server-side LLM explanation pipeline behind signed-in macro data; no guest surface.
- Macro strategy screens with the flag on (`MACRO_STRATEGY_ENABLED=1`: `/macro/transmission`, `/macro/history`, `/macro/review` and their tabs, explanation prompts shipped as a module #299 `src/lib/macro/strategy/prompts/macro-explain-v1.ts`, gzip manifest blobs above 100 kB #302 `src/lib/macro/strategy/db.ts`) need a migrated macro strategy DB + session; only the flag-off state (four tabs, three routes render the 404 page, #300) is driven in [macro-workbench.md](macro-workbench.md).
- Topic public version view licence masking (#297, migration `20261211090000_topics_excerpt_licence_mask.sql`, `src/lib/topics/{masking,public-read}.ts`), judgment card leftovers (#298, `src/components/judgments/`), Company Research merged-issuer lineage in overview / packet / events (#303/#304, `src/lib/company/lineage-read.ts`, `src/lib/company/handlers/{overview,packet,events}.ts`) and the broker-research R15 fixes (licence re-check, atomic bind/unpublish/summary approval, evaluation inputs, F3 deadline — #305–#307, migration locked in #311): all need topics/judgments/issuer/broker-research data over a migrated Supabase; not driveable in guest or gate mode.
- US industry aggregation method `industry-agg-us/1.1` (#310, `src/lib/industry/{method-us,aggregate-us,read,replay}.ts`): a foreign filer whose USD row is only a convenience translation of a non-USD fact for the same period is excluded with reason `dual_currency` (new copy `industries.json` → `dual_currency`, zh `以其他币种申报；申报文件中的美元数为折算值，不采用`) and stays in the coverage denominator; 1.0 runs replay under the 1.0 rule. Visible only in the `/intel/industries/[scheme]/[code]` cell source drawer's excluded-reason summary (`src/components/industries/SourceDrawer.tsx`) and method panel with aggregated US runs over a migrated Supabase; guest only renders the fail-closed state.
- Analyst workspace + Feishu simulation (#316–#320): `/analyst` and `/analyst/[analystId]` pages with recommendation / receipt times shown in Beijing time (#318, `src/lib/analyst/recommendation-time.ts`, `src/components/analyst/{BookTables,RecommendationForm}.tsx`, `src/components/portfolio/DecisionForm.tsx`, `src/components/research/PlaybookRegisterForm.tsx`), the paginated score refresh `POST /api/analyst/scores?afterTicker=` with named skip reasons recovered from completed multi-source daily bars (#316, `src/lib/analyst/score-store.ts`, `src/lib/scoring/daily-bars.ts`, scoring-only provider chain `resolveScoringKline` in `src/lib/data/kline/reliability.ts` + Tencent US bars in `src/lib/data/sources/tencent.ts` — chart `/api/kline` provider order is unchanged), and the switched-on Feishu simulation import `POST /api/integrations/feishu/simulation` (#317, migration `20261213090000_feishu_simulation_ingestion.sql`, locked in #320; needs `FEISHU_SIMULATION_INGEST_{ENABLED,TOKEN}`, `FEISHU_SIMULATION_OWNER_ID`, `FEISHU_SIMULATION_ANALYSTS` and a migrated Supabase): all need a signed-in user / migrated DB. Only the switched-off 404 is driven, in [auth-gate.md](auth-gate.md). The local Feishu connector / analyst-replay demo (`demos/analyst-replay/`, `npm run demo:feishu`, local-model suggestion parsing #319, `scripts/ci/feishu-simulation-e2e.mjs`) is a demo/CI tool, not a product surface.
- Data-source layer + Chinese industry vendor data (#322–#332): admin-only `/admin/sources` content (source catalogue and routing checks `src/lib/sources/{catalog,admin-view,admin-reader}.ts`, `src/app/(app)/admin/sources/`, #325/#331), the Gildata vendor ingestion and read layer (`src/lib/industry/vendor/`, `src/lib/vendor/gildata/`, `GET /api/admin/industries/vendor`, `GET|POST /api/cron/industry-vendor-sync`, `scripts/industry/vendor-sync.ts`, off unless `INDUSTRY_CN_VENDOR_ENABLED=1` + `GILDATA_API_KEY`, migration locked in #328; admin-only page read layer `page-read.ts` #332 — the Chinese industry pages are still an open PR): all need an admin session over a migrated Supabase (and a cron secret for the sync).
