# Auth gate (signed-out access control)

`src/middleware.ts` + `src/app/(app)/layout.tsx`. Only `/`, `/about`, `/login`, `/register`, `/forgot-password`, `/reset-password`, `/design`, `/auth/*` and `/api/*` are public. Every other path redirects signed-out users to `/login?next=<destination>`, where the destination is sanitized by `src/lib/auth/return-destination.ts` (#208). API routes enforce auth themselves (e.g. `/api/portfolio` → 401).

## Sub-features
- Protected page → `/login?next=<path>`. `/en/<protected>` drops the `/en` prefix from `next`. `/today` and `/dashboard` permanently redirect to `/macro`. With the gate enabled, the chain ends at `/login?next=/macro`.
- Return-destination sanitizing (#208): `next` keeps only a literal local path. Query strings are dropped except one valid portfolio ticker on `/portfolio` (#342: `/portfolio?s=00700.HK&token=x` → `next=/portfolio?s=00700.HK`, normalized — `/en/portfolio?s=000333.sz` → `next=/portfolio?s=000333.SZ`; a repeated or invalid `s` → `next=/portfolio`; OAuth sign-in now carries the sanitized `next` through `/auth/callback`) and allowlisted `/intel/industries` selectors (`scheme`, `metric`, `level`, `duration`, `view`, `periods`; one valid value each, re-emitted in that order). The `/en/<protected>` hop applies the same sanitizing. Auth/API paths and anything non-literal fall back to `/macro`; email login and `/auth/callback` honour the sanitized `next` (only `/reset-password` / `/en/reset-password` bypass it for recovery).
- `/login` shows email + password inputs (Supabase password auth; OAuth buttons only for providers listed in `NEXT_PUBLIC_AUTH_OAUTH_PROVIDERS`).
- API: `/api/portfolio` signed out → 401 `{"error":"not authenticated"}`. Feishu simulation import (#317, `src/app/api/integrations/feishu/simulation/route.ts`): with `FEISHU_SIMULATION_INGEST_ENABLED` not `true` (launch pins it empty) `POST /api/integrations/feishu/simulation` → 404 `{"error":"not_found"}` before token or body are read, in both modes. Only with the flag on does the middleware skip the session lookup for that exact POST; the route then authenticates a bearer token itself (503 `integration_unavailable` / 401 `unauthorized` / 415 / 413 / 400 / 403 `owner_mismatch`) and needs a migrated Supabase — not driven. Admin-only Gildata industry data (#324/#332): `GET /api/admin/industries/vendor` signed out → 403 `{"error":{"code":"unlicensed",...}}` in both modes, and `GET /api/cron/industry-vendor-sync?job=gildata-memberships` → 503 `cron_unavailable` because launch pins `CRON_SECRET` (and `INDUSTRY_CN_VENDOR_ENABLED`, `GILDATA_API_KEY`) empty. Owner-scoped Feishu overview (#339, `src/app/api/integrations/feishu/overview/route.ts`): with the ingest flag off `GET /api/integrations/feishu/overview` → 404 `{"error":"not_found"}` before any token check, in both modes (with the flag on, the middleware skips the session for that exact GET and the route checks the connector token itself — not driven). Licence-gated SW2021 vendor replay (#335, `GET /api/industries/vendor/replay`) → 403 `unlicensed` in both modes (no licence row is readable, so access fails closed). Analyst report board API (#341, `GET /api/analyst/report`) signed out → 401 `{"error":"unauthenticated"}` in both modes. `/api/watchlist` without Supabase → 200 `{"error":"Supabase not configured (guest mode uses localStorage)"}`.
- When Supabase env is **absent**, the gate is deliberately off (local dev), so the Macro Workbench shell renders at `/macro` (its guest content is mapped in `macro-workbench.md`).
- Admin-only `/admin/sources` (#331, read-only data-source catalogue): signed out it lands on `/login?next=/admin/sources` in both modes — via the middleware in gate mode, via the page's own admin check in guest mode (the gate is off there, but the page still requires an admin). A signed-in non-admin sees a denied notice; only an admin sees the catalogue.
- SW2021 Chinese industry pages (#333/#335, `src/components/industries/cn/`): in guest mode `/intel/industries?scheme=sw2021` renders the licence-pending notice `中国行业数据授权待确认` with a switch back to SIC, and no vendor numbers; in gate mode it is a protected page (see the `/intel/industries` sanitizing cases).
- Analyst report board `/analyst/report` (#341): in guest mode the page renders, its API answers 401, and it shows `请登录绑定的正式模拟账户查看报表。` with a link to `/login?next=/analyst/report`; in gate mode the middleware sends it to `/login?next=/analyst/report`.
- Not provable locally: an actual sign-in (so the post-login jump to the sanitized `next`), the `/login` → `/macro` bounce for a signed-in user, admin-only `/research` (403 for non-admins), the `/admin/sources` denied notice and catalogue, vendor industry data, and the vendor cron's `job_disabled` / run branches (need a cron secret); the SW2021 pages with vendor data (admin preview or a public licence), the report board with data (`group_not_configured` 503 / `group_access_denied` 403 need a signed-in user), and the switched-on Feishu overview.

## How to get to it (user POV)
A signed-out visitor clicks any product link (今日 / 组合 / 股票池) or opens a deep link.

## Driving it with HTTP + CDP browser
- Guest mode: `node $S/drive.mjs auth-gate` checks the `/api/portfolio` 401 JSON, the switched-off Feishu simulation POST 404 `not_found` (also checked in gate mode; evidence `auth-api-feishu-simulation-<mode>.json`), the Gildata vendor API 403 `unlicensed` and vendor cron 503 `cron_unavailable` (both modes; `auth-api-admin-industries-vendor-<mode>.json`, `auth-api-cron-industry-vendor-sync-<mode>.json`), the switched-off Feishu overview GET 404 `not_found` (`auth-api-feishu-overview-<mode>.json`), the vendor replay 403 `unlicensed` (`auth-api-industries-vendor-replay-<mode>.json`) and the analyst report API 401 `unauthenticated` (`auth-api-analyst-report-<mode>.json`), all in both modes, `/admin/sources` → `/login?next=/admin/sources` (both modes), the `/login` inputs, both 308 aliases, that opening `/today` shows the Macro Workbench heading at `/macro`, the guest SW2021 licence-pending notice (`auth-industries-sw2021-guest.png`) and the guest `/analyst/report` sign-in alert (`auth-analyst-report-guest.png`). This checks access to the shell. Macro data requires a configured database.
- Gate mode: `OSB_MODE=gate $S/launch.sh` then `node $S/drive.mjs auth-gate`. It checks both 308 aliases, then asserts exact login destinations for `/macro`, the two aliases, `/portfolio`, `/en/portfolio`, and `/watchlist`, plus five sanitizing cases: `/portfolio?s=00700.HK&token=x` → `next=/portfolio?s=00700.HK`, `/en/portfolio?s=000333.sz` → `next=/portfolio?s=000333.SZ`, `/portfolio?s=00700.HK&s=NVDA` → `next=/portfolio` (#342), `/intel/industries?metric=roe&scheme=sw2021&token=x` → `next=/intel/industries?scheme=sw2021&metric=roe`, and `/en/intel/industries?view=table&level=9` → `next=/intel/industries?view=table`; plus the research hub and topics pages (#278/#273/#275): `/intel` → `next=/intel`, `/intel/topics` → `next=/intel/topics`, `/intel/topics/ai-capex?asOf=x` → `next=/intel/topics/ai-capex` (query dropped; middleware redirects before the topics switch is consulted); and `/analyst/report` → `next=/analyst/report` (#341). It also checks that `/` stays public. Screenshots `auth-login-<mode>.png`, `auth-gate-redirect.png`.

## Gotchas
- Gate mode is a stand-in: Supabase points at `http://127.0.0.1:54399` (closed) with a dummy anon key, so `getUser()` fails and every request is treated as signed out. It proves the redirect/allow-list logic, not real session handling. Those values are placeholders, not secrets.
- Next's dev route announcer is also `role=alert`; wait on the report board's own text, not on the role.
- In gate mode the watchlist and stock journeys are not meaningful (pages redirect), and `/api/search` returns 503. `drive.mjs all` only runs landing, quote-api and auth-gate there.
- Each middleware request in gate mode attempts a connection to the dead port. That is fast locally (connection refused), but a firewall that drops instead of refusing would make every page slow.
