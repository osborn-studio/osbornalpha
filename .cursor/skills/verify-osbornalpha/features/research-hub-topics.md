# Research hub (/intel) + Topics (switched-off state)

`src/app/(app)/intel/page.tsx` renders the research hub (#278): a `PageHeader` `研究` / `Research` and five entry cards in research-chain order (`HUB_ORDER` from `src/components/research-ui/chain.ts`, card shell `src/components/intel/hub/HubCard.tsx`), followed by the older 发现 / 我的研究 tabs (wizards, watchlist screener, private artifacts). Topic research (#270–#279: `src/lib/topics/`, `src/app/(app)/intel/topics/`, `src/app/(app)/admin/topics/`, `src/app/api/topics/`, `src/app/api/admin/topics/`) is behind a server switch: `TOPICS_ENABLED=1` (`src/lib/topics/flags.ts`), plus the public flag (`topic_settings.public_enabled`, read over service-role Supabase by `src/lib/topics/public-flag.ts`) for non-admin readers.

## Sub-features
- Hub cards, each `section[data-entry][data-hub-state]` with a `[data-hub-step]` number `01`–`05`: `macro` (`MacroSummaryCard`), `industries` (`IndustryEntryCard`, US · SEC SIC / 中国 · 申万 2021 links), `companies` (static, `data-testid="intel-companies-card"`), `foreign` (`ForeignEntryCard`), `topics` (`TopicEntryCard`, `data-testid="intel-topics-card"`). Foreign and topics fetch their public API (`/api/broker-research/reports`, `/api/topics?limit=200`) and are `open` only on a 200 with a well-formed body (`hub-model.ts`); otherwise `notServed` (`aria-disabled`, `未服务` / `Not served` badge, no enter link).
- Guest: 01–03 open with enter links `/macro`, `/intel/industries?scheme=sic`, `/intel/companies`; the macro card fails closed with `宏观数据暂不可用` / `Macro data unavailable`; 04 and 05 are not served. The research chain on `/intel` has no current step (no step matches the bare `/intel` path).
- Topics switched off (guest/gate launch pins `TOPICS_ENABLED=` and `TOPICS_E2E_FIXTURES=` empty): `/intel/topics`, `/intel/topics/<slug>`, `/intel/topics/<slug>/v/<n>` and `/admin/topics` (+ `/new`, `/<id>`, `/<id>/publish`) call `notFound()` → app 404 page `页面不存在`. `GET /api/topics*` checks the session first → 401 `unauthenticated`; `GET /api/admin/topics*` → 404 `topics_disabled`, and so do the topic summary admin actions (#287) `POST /api/admin/topics/<id>/summary` and `POST /api/admin/topics/<id>/summary/<summaryId>/{approve,discard}` (`adminPost` in `src/lib/topics/admin-route.ts` checks the switch before the session and the body); crons `/api/cron/topic-drift` and `/api/cron/topic-verify` → 503 `cron_unavailable` while `CRON_SECRET` is unset, 401 with a wrong secret, `{skipped:'disabled'}` with topics off (ops-only, `src/lib/topics/cron-route.ts`).
- With topics on (not driveable here, see Gotchas): directory with category filter + search + cursor (`src/components/topics/directory/`), dossier with version bar, judgment/series/evidence blocks, source drawer and asOf replay (`src/components/topics/dossier/`), admin editor (three-column outline / text / evidence picker, lint, draft) and publish page (disclosure check, preview, summary block — generate / approve / discard a per-locale LLM summary that is frozen into the published version, #287 `src/components/topics/admin/publish/SummaryBlock.tsx`, `src/lib/topics/summary/` — publish / unpublish / retire dialogs, versions table with replay verify) under `src/components/topics/admin/`, the Copilot `topic_dossier` tool (#290, `src/lib/topics/copilot.ts`, registered in `src/lib/agent/tools.ts` only when `TOPICS_ENABLED=1`), research-chain step 05 and hub card 05 become links to `/intel/topics`, and the hub card shows published count / latest title + version / revised count.

## How to get to it (user POV)
Top nav / bottom tab `研究` (or any `/intel/*` page's chain) → `/intel`. Topics would be entered from hub card 05 or chain step 05 once served.

## Driving it with CDP browser + HTTP
`node $S/drive.mjs intel-hub` (guest only; in gate mode `/intel` and `/intel/topics…` redirect to login, which the `auth-gate` journey asserts). Fresh zh-CN and en-US contexts open `/intel` (domcontentloaded, then wait until no card is `loading` and the macro card shows its unavailable text), save the five cards to `intel-hub-cards-<lang>.json`, and check: 200 + h1 starting with `研究` / `Research`; five cards in order `01:macro 02:industries 03:companies 04:foreign 05:topics`; 01–03 `open` with their enter links; 04/05 `notServed`, `aria-disabled=true`, no link, `未服务` / `Not served`; the macro card's fail-closed text; and the research chain (01–03 linked, none current, 04/05 not served). Then `/intel/topics`, `/intel/topics/ai-capex`, `/intel/topics/ai-capex/v/1` and `/admin/topics` must show the 404 heading and no topic content, `GET /api/topics?limit=200` → 401 `unauthenticated`, `GET /api/admin/topics` → 404 `topics_disabled`, and the three summary POSTs (generate / approve / discard, placeholder UUIDs, JSON body) → 404 `topics_disabled` (bodies `api-topics-guest.json`, `api-admin-topics-guest.json`, `api-admin-topics-summary-guest.json`). ## Gotchas
- `/intel` never reaches `networkidle` (the screener/hub keep requests going); wait on DOM state, not the network.
- Under `next dev` the topics 404 is served with HTTP **200** (the `(app)` layout has `loading.tsx`, so the response has started streaming before the page calls `notFound()`); assert the rendered 404 heading (plus `noindex`), not the status code.
- `TOPICS_E2E_FIXTURES=1` (`src/lib/topics/e2e-fixture.ts`) turns topics on with synthetic fixtures whenever Supabase is unset and `NODE_ENV` is not production — i.e. in exactly this skill's guest mode. It feeds the repo's Playwright suite (`e2e/topics.spec.ts`, `e2e/topics-admin.spec.ts`; runbook `docs/runbooks/topic-research.md`, #279), is not product data, and is deliberately pinned off by `launch.sh` (same rule as `INDUSTRY_E2E_FIXTURES`).
- Not provable locally: topics with real data need `TOPICS_ENABLED=1`, a migrated Supabase with the topic tables (#271/#272), a signed-in session for `/api/topics*` and the public pages, `topic_settings.public_enabled=true` for non-admins (admins get a preview projection), and an admin user (`requireAdminUser`) for `/admin/topics*` + `/api/admin/topics*` (editor, evidence search, lint, preview, disclosure check, summary generate / approve / discard, publish / unpublish / retire, settings, version replay verify). Summary generation also needs LLM credentials and meters the `topic_summary` usage feature (#287/#288, migration `20261210093000_usage_feature_topic_summary.sql`); the Copilot `topic_dossier` tool (#290) needs topics on plus a working Copilot (LLM). The evidence-ref contract (#270, `src/lib/evidence/`) and the drift / replay crons (#278) have no UI of their own.
