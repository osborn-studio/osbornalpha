# 飞书分析师评分与历史行情回放

分析师在与正式分析模块一致的表单中登记建议。系统读取真实的已收盘日线，用前向评分和模拟账本函数计算第 5 和第 10 个交易日的表现。连接机器人后，成员登记后即发本人结果，全组登记齐全后发评分汇总。PM 核对行情与评分后，系统另发验收结论。建议、行情证据、验收记录与消息回执保存在本机 SQLite。

## 启动与入场

在仓库根目录运行 `npm run demo:analyst`，打开 `http://127.0.0.1:4317/`。首页点击 **分析师 A、分析师 B 或 PM** 即可进入。工作台右上角的「切换身份」返回角色选择页，切换时使用同一本机数据。可以在几个标签页分别选择不同身份，模拟多人同时操作。生成的本机启动页也可通过 `open build/analyst-replay/start.html` 打开。

角色密钥与数据库存放在 Git 忽略的 `build/analyst-replay/`。服务重启可继续已有场次。本机测试模式提供直接选择身份，部署为 HTTPS 共享场次时通过各成员的私有邀请登录。

## 通过飞书群提交建议

正式群使用独立的 [Osborn Alpha 正式飞书连接器](../../integrations/feishu/README.md)。本节用于 Demo 联调，建议为 Demo 单独配置飞书应用。

在 `build/analyst-replay/feishu-app.env` 填入自建应用的 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`，将文件权限设为 600。使用 Node 22，在 Demo 服务运行期间另起 `npm run demo:feishu`。出现「飞书长连接已在线」后，在飞书开发者后台保存长连接订阅，添加「接收消息」事件 `im.message.receive_v1`，发布并将应用机器人加入测试群。机器人需要以应用身份发送消息的权限。成员显式 @机器人时可用群内 @ 权限，如需接收未 @ 的「同意」，申请获取所在群全部消息的权限。

测试成员在群里 @应用机器人发送「联调」。PM 进入本机 Demo 的「群播报 → 飞书群配对」，根据收到的群和成员指定分析师与确认人。多个成员可先后联调，显示名由 PM 选定的分析师档案提供。群成员提出建议后，指定确认人直接回复机器人发出的摘要「同意」，应用会回报登记结果。示例中的姓名应与绑定的分析师一致。

成员的群名与正式姓名不同时，可在本机私有配置 `feishu-bindings.json` 的 `analystAliasesByRole` 中按角色填写群名列表，例如 `{"A":["甲组研究员"]}`。PM 配对时可查看允许使用的署名。已绑定的成员可用自己的正式姓名或群名提交，机器人摘要统一显示正式姓名。

PM 的目标群列表也会显示已预先绑定的分析师。首次收到该成员的配对消息后，列表会显示实际配对编号和机器人回复状态。

已绑定的分析师 @应用机器人发送「我想加仓腾讯控股」。语言模型提取标的、动作和已填写的选填项，本机根据飞书发送者确定分析师，并核验证券代码、市场和字段。需要保留价格或研究信息时，也可以发「我想加仓腾讯控股，参考价447.4港元，目标480，止损420」。参考价、目标价、止损价、理由、关联研究和期限均可省略。信心默认与页面一致，为 70%。未注明建议时间时以原消息发送时刻登记。历史回放可以写「建议时间 2026年6月16日 16:30」，摘要以北京时间显示。

如果只发「我想加仓」，机器人会追问标的。原分析师直接回复「腾讯控股」或「00700.HK」即可继续。公司名会匹配证券主表，命中多个上市市场时可直接回答「港股那只」。如果有多条待补的建议，请回复对应的追问。字段齐全后，PM 直接回复机器人发出的待确认摘要「同意」。

需要同时申请模拟成交时，请写明本次股数和模拟每股成交价，例如「我想给腾讯控股加仓100股，模拟成交价447.4港元」。成交申请缺项时会追问。原分析师可以直接回复取消模拟成交并保留建议，或在 PM 确认前撤回整条建议。改为仅登记建议时，PM 需要确认新摘要。原有竖线格式仍可使用。Demo 登记和正式系统同步分别保留回执，重复确认沿用同一提案编号。

### 直连本机模型或阿里云百炼

连接器可以通过 OpenAI 兼容接口提取自然语言建议。在私有的 `build/analyst-replay/feishu-app.env` 配置以下变量，然后重启连接器。使用本机 Ollama 时，模型名需和本机模型列表一致，API Key 可以省略。

```dotenv
FEISHU_LLM_BASE_URL=http://127.0.0.1:11434/v1
FEISHU_LLM_MODEL=inkling-2-mini:26b-a5b-nvfp4
FEISHU_LLM_TIMEOUT_MS=35000
```

切换到百炼时，使用 API Key 所属地域的 HTTPS OpenAI 兼容 Base URL 和文本模型名，并在同一私有文件配置 `FEISHU_LLM_API_KEY`。本机和百炼通过配置显式切换。连接器仅将已绑定分析师 @机器人的文本和同一提案的补充交给模型。可以直接问「你有什么功能」或在草稿里问「还差什么」。证券查询只使用模型从当前消息提取并核对过的公司名。认证、代码核验、审批和登记由连接器处理。模型暂时不可用时，机器人保留草稿并提示回复重试。[Ollama 兼容接口](https://docs.ollama.com/api/openai-compatibility) · [阿里云百炼兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)

### 启用飞书 Aily 提取建议

在飞书 Aily 创建并发布工作流，开启「渠道管理 → 开放接入 → 支持使用应用身份调用 API 和 SDK」。现有群机器人继续收发消息，使用这个工作流对应的飞书渠道应用凭证调用 Aily 技能。工作流只需开始节点、模型节点和结束节点。[Aily 应用身份接入说明](https://aily.feishu.cn/hc/8qluoxsa_mqnk8i5v) · [技能调用接口](https://aily.feishu.cn/hc/8qluoxsa_kmcc4e3h)

开始节点输入 `text`（String）、`receivedAt`（String）、`isSupplement`（Boolean）、`priorFields`（String，已识别字段的 JSON）。结束节点输出 `extraction`（String，以下结构的 JSON）。模型只提取当前消息中分析师明确表达的内容。字段证据须逐字来自当前消息。未提及的字段省略。分析师署名、身份、批准和执行由本机处理。

```json
{
  "intent": "proposal",
  "fields": {
    "action": {"value": "add", "evidence": "仓位往上调一点"},
    "ticker": {"value": "00700.HK", "evidence": "腾讯控股"}
  }
}
```

`intent` 可用 `proposal`、`other`、`ambiguous`。动作可用 `buy`、`add`、`trim`、`sell`、`hold`、`pass`。还可提取 `rationale`、`thesis_ref`、`reference_price`、`target_price`、`stop_loss`、`confidence`。询问、转述、未达到的条件、闲聊归为 `other`。多只证券或多个互斥动作归为 `ambiguous`。

在连接器的私有 `build/analyst-replay/feishu-app.env` 填好以下四项后重启连接器。建议用 Aily API 调试台先验证示例输入与输出。连接器只向 Aily 提交已绑定分析师主动 @机器人的文本，以及他们对同一条提案追问的补充。技能超时时，连接器保留草稿并提示回复重试。

```dotenv
FEISHU_AILY_APP_ID=
FEISHU_AILY_SKILL_ID=
FEISHU_AILY_CHANNEL_APP_ID=
FEISHU_AILY_CHANNEL_APP_SECRET=
```

### 接入正式系统的专用模拟账号

在目标系统部署 `/api/integrations/feishu/simulation` 及对应数据库迁移后，由该系统管理者配置 `FEISHU_SIMULATION_INGEST_ENABLED=true`、`FEISHU_SIMULATION_OWNER_ID`、`FEISHU_SIMULATION_ANALYSTS`（Demo 角色 ID 到该账号内已有分析师 UUID 的 JSON 对象）和专用 `FEISHU_SIMULATION_INGEST_TOKEN`。使用至少 32 个字符的随机接入令牌。目标服务使用自己的 Supabase 服务端凭证。

在连接器的本机环境配置 `FEISHU_SIMULATION_ORIGIN` 和匹配的 `FEISHU_SIMULATION_INGEST_TOKEN`，在本机 `feishu-bindings.json`（与数据文件同目录）配置 `simulationAccount`，格式为 `{"id":"目标模拟账号 UUID","confirmed":true}`。重启连接器后发送新的建议。摘要会标示本次写入的模拟账号尾号。应用按买入／加仓、卖出／减仓分别记入模拟组合，建议、采纳决定、成交和持仓在一次数据库事务内保存；持有、观望及没有填写成交参数的建议仅登记建议。正式账户未绑定时，群内确认仍可登记 Demo，既有 Demo 回执可供核对。

群消息识别运行在本机连接器，模型配置或提示词更新后重启该进程即可生效。正式系统同步和回执由主队列处理，Demo 登记与回放在后台队列独立处理。

## 可选的跨电脑共享场次

共享场次通过 HTTPS 转发到仅监听本机的 Demo，使用独立数据库。临时彩排可先开启 Cloudflare Quick Tunnel，把它指向单独的本机端口。

```sh
cloudflared tunnel --url http://127.0.0.1:4328
```

把终端显示的 HTTPS 站点地址填入 `REPLAY_PUBLIC_URL`，使用同一端口启动共享场次。

```sh
REPLAY_PORT=4328 REPLAY_DATA_DIR=build/analyst-replay-shared \
  REPLAY_PUBLIC_URL=https://示例.trycloudflare.com npm run demo:analyst
```

组织者打开本机 `build/analyst-replay-shared/start.html`，将初始分析师和 PM 的邀请链接分别私发给对应成员。完整邀请链接包含对应角色的访问码。PM 进入共享页的「机器人设置」连接飞书，并发送测试消息确认送达。

共享服务和隧道都需要在演示期间保持运行。重建临时隧道后，使用新地址重启共享服务，重新生成并分发角色邀请。[Cloudflare Quick Tunnel 说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

## 添加分析师

PM 在「分析师评分」的「新建分析师」填写显示名称，可选真人或 Agent 类型和备注。创建后可直接从本机首页选择该身份。共享场次通过私发的邀请链接让新增成员登录。每位分析师可以登记建议、查阅个人账本和记录成交。PM 可在「交易记录」按分析师筛选。

每条建议进入该分析师尚未提交的最早一组。需要开新组时，系统将当时已建档的分析师加入本组。已开组的成员名单固定，后来添加的分析师参与后续组。全组登记齐全后，PM 可按组核对和验收。

## 现场登记与验收

1. 用分析师 A 的入口打开「分析师评分」，填写本人的标的和建议。标的默认留空，建议时间按北京时间（UTC+8）录入。点击「使用当前北京时间」可回到现在；需要立即演示已满 10 个交易日的样例时，点击「填入历史回放示例」即可填入腾讯控股和 2026 年 6 月 16 日。市场、动作、参考价、信心、目标价、止损、建议期限、关联研究、建议时间及理由都可编辑。建议期限只记录分析师预计的持有或观察时间，默认「未定」，选择 5 日或 10 日不改变系统计分窗口。服务端按标的所在交易所日期选择基准收盘。
2. 点击「登记建议」。服务端读取已完成的交易日线，返回命中结果和评分。每位分析师提交后，机器人发送该建议的标的、动作和评分结果，观察期未满时标明暂评或待评。本人可展开「核对行情与登记详情」对照原文、行情来源、基准日和后续收盘价。参考价、目标价及止损是建议内容，模拟成交价采用基准交易日收盘。
3. 同组其他分析师打开各自入口登记。建议理由和研究引用等完整登记内容在工作台查看。全组登记齐全后，组内分析师和 PM 均可打开本组明细，机器人播报全组评分汇总和累计命中率。
4. PM 在「评分结果」展开本组的「核对行情与登记详情」，核对标的、基准收盘、观察日和评分。在「PM 验收」选择批次，填写验收说明，再点「通过」或「退回」。待评分可以退回，暂评和已满 10 日的结果可针对当时的行情版本验收。验收结论和说明发到群里。暂评更新为正式评分后可重新验收，历史意见随原行情版本保留。顶部「群播报」可核对消息与回执。

### 行情接口与评分口径

支持 A 股、港股和美股。服务使用正式系统的已收盘日线筛选与多行情源回退。已配置 `DATAGATEWAY_BASE_URL`、`DATAGATEWAY_API_KEY` 时先请求网关并校验返回的复权口径，启动命令会加载仓库的 `.env.local`。A 股使用前复权，港股和美股使用不复权。接口取数的时间预算为 32 秒。腾讯控股的配套日期另有经校验的真实离线快照，使用时标注「历史快照」。同一标的、市场和建议交易日已核验的完整窗口会保存在本机，以便两人按相同价格核对。

**现场展示口径**为「历史行情回放，按已完成的实际交易周期计分」。以建议日对应的交易日收盘为基准，在第 5 和第 10 个后续交易日分别核对方向命中及评分。总览的命中率按第 5 日方向统计，平均评分采用第 10 日评分，已满 5 日但未满 10 日的建议使用暂评分。旧版已结算的 20 日结果保留原口径。

已满 10 日的历史建议提交后直接取价计算。按当前时间登记的建议先保存，第 5 日收盘到齐后产生暂评。取数失败或未覆盖建议日会提示行情暂缺，可用顶部或单条记录的「刷新评分」重新核对。

总览卡显示命中率和有效样本数，点「查看账本」可核对持仓、均价、收益和建议时间线。本人账本还包含信心自评。晚于建议日登记的历史回放按原规则排除出自评的独立样本。

## 记录已成交的交易

分析师打开顶部「交易记录」，或从自己的一条建议点击「记录成交」带入标的和市场。根据实际成交回报填写买入或卖出、成交价格、股数、费用及北京时间，点击「确认成交」。成交时间留空使用提交时刻。交易记录可独立创建，无需先登记建议或等待历史行情。

成交写入 Demo 的本地 SQLite 账本。买入费用计入加权平均成本，卖出费用扣减已实现盈亏，卖出股数按成交时点的持仓校验。分析师可查看自己的流水。PM 可按分析师核对各自的流水、持仓与已实现盈亏。模拟建议的成绩与实际成交的盈亏各自计算。交易功能没有连接券商下单或正式系统账户。

## 可选的双人分步回放

切换到「双人回放」可使用固定的两轮行情按阶段揭晓。分步回放和即时登记分别记账。

1. PM 点击「开始演练」。分析师查看当轮决策日及之前的腾讯控股收盘价。鼠标移至曲线或使用左右方向键可查看各交易日价格。
2. 两位分析师分别选择建议动作，填写理由及信心，点击「提交本轮建议」。首人提交后，另一方与 PM 只能看到提交进度。第二人提交后，本轮建议锁定并同时公布。
3. PM 点击「揭晓 T+5」和「揭晓 T+10」。每次揭晓都会在服务端用当时可见的日线计算两人的结果，再更新三个页面和群播报。总览卡同步更新，个人账本列出命中数、有效样本数和平均评分。
4. PM 点击「开启下一轮」。完成第二轮后选择「进入验收」，在「评分核对明细」逐条比较日期、价格、收益、命中与评分。展开建议动作可查看登记时的理由及信心。
5. PM 填写验收说明后通过或退回。三个页面均可查看结论。PM 可从终态新建空白场次，历史场次保存在数据库中。

## 分步回放用的固定行情

快照包含从腾讯财经接口取得的 120 个港股交易日收盘价，标的是腾讯控股（00700.HK），单位为港元，口径为不复权。来源 URL、取数时间、原始响应的 SHA-256 和价格在 [行情文件](./tencent-hk00700.json) 中。服务启动时校验快照指纹，浏览器只取得当前可见的交易日。两轮决策日为 2026-06-16 和 2026-09-03。

买入和加仓按上涨方向计分，卖出、减仓和观望按下跌方向计分。持有建议记录观察收益。系统在第 5 和第 10 个后续交易日分别检查方向，把方向调整后的百分比收益保留至一位小数作为评分。第 10 日揭晓前，分数暂用第 5 日结果。代码复用正式系统的 [方向评分函数](../../src/lib/scoring/forward.ts) 和 [账本函数](../../src/lib/analyst/book.ts)。

## 飞书群播报

初始使用本地 HTTP 接收器。目标群完成配对后，PM 可在本机「群播报 → 飞书机器人设置」选择「使用已配对的飞书群」。之后的页面评分、全组汇总与 PM 验收结果由应用机器人发往这个群。连接器暂时离线时，消息留在队列。已绑定的确认人在群里回复建议摘要后，机器人会在原消息下回复个人结果。PM 可在「群播报」核对页面操作的投递记录。

使用自定义机器人时，填写 webhook 和可选签名密钥，点击「连接飞书」。点击「发送测试消息」会实际发到所选目标。切换渠道只影响之后的操作，每条已有消息保留原投递目标。开启关键词校验的机器人需配置能匹配每条播报的关键词。支持飞书和 Lark 官方的自定义机器人地址。[飞书官方说明](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)

配置及密钥存储在本机的数据目录，仅 PM 可更新，接口仅返回配置状态。每条卡片附场次及事件号。遇到限流会排队重试。超时且接收情况不明时显示「送达待核实」，PM 可先在群内按事件号核对，再决定是否重发。通过「切回本地接收」可恢复本地彩排。确认已部署可达的演示入口后，可用 `REPLAY_PUBLIC_URL` 为卡片附上普通站点链接，链接中不应包含角色密钥。

## 验证

从仓库根目录运行以下命令。各套验证使用独立临时目录和本地接收器，正常启动的演示场次可同时保留。

```sh
node --import tsx --test demos/analyst-replay/*.test.mjs
node demos/analyst-replay/browser-smoke.mjs
```

浏览器验收需要项目使用的 Playwright Chromium。脚本打开独立浏览器上下文验证默认双人流程，随后用 PM 创建第三位分析师，核对独立邀请、组成员、评分、PM 验收和播报。脚本也检查两轮分步回放，还在洛杉矶设备时区验证北京时间当天的建议与成交流水。桌面和手机视图截图保存在 `build/analyst-replay-qa/`。

正式系统同步的隔离验收需要已安装的仓库依赖、Node 22.19 或以上的 22.x 版本，以及运行中的 Docker Desktop（`desktop-linux` 上下文）。请提前在该上下文准备 `postgres:17-alpine` 和 `public.ecr.aws/supabase/postgrest:v16.2` 镜像。

```sh
node --import tsx scripts/ci/feishu-simulation-e2e.mjs
```

脚本模拟飞书消息收发，使用仓库内的历史行情快照，以及实际的 Demo HTTP 服务、正式登记接口和数据库迁移。它用隔离测试账号和临时数据库验证评分、建议、模拟成交、持仓，以及回执丢失后重试的去重行为。脚本结束时清理临时容器和数据。

可用 `REPLAY_PORT` 更改监听端口，或用 `REPLAY_DATA_DIR` 指向另一份演示数据。每个运行中的服务独占其数据目录。
