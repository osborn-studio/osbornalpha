**Verdict: not ready for implementation planning.** The architecture is salvageable, but several rules deterministically produce incorrect historical answers, and the proposed Tushare path cannot yet substantiate the primary-source/replayability mandate. The biggest blockers are vintage deduplication, disclosure timestamps, historical issuer resolution, and non-atomic publication. I reviewed the requested code and primary API documentation; no files were modified.

**Verify before implementing**

- **Tushare originals and revisions:** Record real type-1/4/5 responses for a known restatement across all three endpoints. Verify whether original announcement dates survive, whether same-date corrections coexist, and whether `update_flag=1` means only “latest.” Documentation confirms type-4/type-5 descriptions, but not complete historical retention.
- **Tushare units and fields:** Current documentation labels `balancesheet.total_share` as **shares**, and lists both `fin_exp_int_exp` and `int_exp`; verify actual values against a report, including banking and non-banking cases. Do not extrapolate units from similarly named daily-market fields. [Balance-sheet fields](https://tushare.pro/document/2?doc_id=36), [income fields](https://tushare.pro/document/2?doc_id=33).
- **Tushare pagination and quotas:** Establish actual row caps, ordering, `has_more` behavior, supported pagination parameters, and production-token limits. I could not substantiate “approximately 100 rows” or six calls per issuer in three seconds as reliable operating guarantees.
- **Tushare calculated versus disclosed rows:** The cash-flow API exposes `is_calc`; verify its default and whether derived rows can enter this ingestion path. Confirm YTD semantics for every loaded report type. [Cash-flow API](https://tushare.pro/document/2?doc_id=44).
- **SEC filing metadata:** Record examples of 10-K, 10-Q, 20-F/IFRS, amendments, and retained `other` forms. Check missing/inconsistent `fy/fp`, accession report dates, and the available acceptance timestamp. Keep `frame` out of identity and do not treat it as a fiscal-period authority.
- **SEC concept availability:** Verify every IFRS spelling against an actual filing taxonomy and response. Test a filer without `Liabilities`, a multi-currency filer, a fiscal-year change, and a multiclass issuer. Determine whether missing share-class facts are omitted rather than returned as conflicting companyfacts entries.
- **Accounting equivalence:** Review fallback definitions against the applicable taxonomy releases—especially parent/total profit, equity with noncontrolling interests, current debt, restricted cash, continuing-operations cash flow, and capex. A changed value alone does not establish a restatement.
- **Operational evidence:** Measure complete processing on large SEC snapshots and a ten-year Chinese issuer. Verify production storage limits, deployed function settings, global SEC request concurrency, and that snapshot metadata never includes the Tushare token.
