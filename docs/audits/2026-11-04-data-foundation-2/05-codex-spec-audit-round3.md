The following are **new defects in the third draft’s mechanisms**, rather than restatements of the outstanding round-2 findings.

| Severity | Section | Issue | Fix |
|---|---|---|---|
| **P1 · R3-1** | §§4.1, 5.2, 6.1 steps 6/8 | **Publication and mapping activation are separate commits.** After `publishStaged`, a crash can leave permanent `ok` rows hidden behind generation 0/old generation; updating several filings exposes a partially activated batch. An older deployed worker can subsequently assign a lower `MAPPING_GEN`, contradicting “highest fully processed generation.” A filing producing zero candidates also needs explicit inclusion to retire its old facts. | Activate a complete processed-filing manifest—including zero-output filings—and publish its facts in one fenced transaction. Reject generation regression; define idempotent recovery and the treatment of quarantined replacement generations. |
| **P1 · R3-2** | §§4.4, 5.4 | **Cleanup deletes legitimate quarantine evidence.** The predicate is merely `status <> 'ok' AND batch_id <> p_batch`. A successful batch containing both published facts and quarantined facts loses its quarantined rows on the next sync, leaving its review items unable to promote them. “Non-ok” does not mean “unpublished abandoned batch.” | Persist completion at issuer/market/generation level; delete only abandoned generations, preserving quarantined facts and associations from completed generations. Whole-batch status alone is insufficient for a multi-issuer batch. |
| **P1 · R3-3** | §§4.4, 5.4, 8 | **The new market-scoped leases protect issuer-wide mutations.** US and CN workers can both legitimately hold leases, yet either worker’s cleanup deletes the other’s staged/quarantined rows because its SQL has no market predicate. Both feeds also enter the same fact-selection keys, while derivation requires market-specific formulas. | Scope ingestion mutations through `filings.market` and the appropriate generation. Separately define source/basis selection for dual-feed reads and derivation, or explicitly prohibit dual-feed ingestion until that contract exists. |
| **P1 · R3-4** | §§4.4, 4.8, 5.4 | **Lease validation is not atomic fencing.** A plain existence check does not hold the lease row against takeover before cleanup/publication executes. `insertFacts`, `updateFiling`, and `setFactStatus` carry no lease token despite “all writes” being fenced. `release` neither checks expiry nor raises on ownership mismatch, contrary to the following paragraph. | Lock and validate the lease within each mutation transaction; require the token for ingestion writes and mapping activation. Give administrative promotion its own serialized contract. Make release’s expiry/error behavior explicit and consistent. |
| **P1 · R3-5** | §§5.2–5.3, 7.1–7.3 | **Same-day ambiguity is arrival-dependent and acceptance breaks its invariant.** If conflicting filings arrive together, both new rows are hidden; if one arrives later, the earlier `ok` row remains authoritative. Accepting the conflict then promotes all matching quarantined rows, allowing different same-day values and restoring an arbitrary `created_at/fact_id` winner. Comparisons also lack an active-generation restriction. | Maintain conflict state for the active K/date interpretations, independent of arrival order; exclude the unresolved conflicting group from current-value selection. Acceptance must select an evidenced interpretation or remain acknowledgement-only, rather than promote every candidate. |
| **P1 · R3-6** | §§4.8, 5.2, 5.4, 8 | **The replacement read contract can silently truncate valid history.** “One request per concept, ≤1,000 rows” is an estimate, not a supported-data bound; multiple intervals, disclosures, units, and retained mapping generations can exceed it. `factsOfIssuer` promises all rows but specifies neither overflow handling nor a snapshot-safe continuation. It also does not specify executing the filing-generation join in the same snapshot. | Define a server-side snapshot read performing the eligibility join and appropriate selection before output limits; provide complete snapshot-pinned history reads for derivation/planning, or fail explicitly on overflow. |
| **P1 · R3-7** | §§5.3, 6.2–6.3 | **Numbers-as-strings changes control fields and equality semantics too.** The scanner converts every numeric token, not just financial values. The adapter contract does not normalize fields such as `is_calc`, numeric response codes, and numeric flags; ordinary numeric comparisons can therefore fail. Equivalent value spellings such as `100000` and `1e5` can also become false conflicts if compared as strings. | Define typed decoding after scanning: explicitly normalize control fields, retain financial values losslessly, and compare candidate values using canonical decimal equality. Test control-field behavior and equivalent numeric spellings alongside unsafe integers. |
