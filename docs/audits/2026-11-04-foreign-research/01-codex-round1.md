Verdict: **Not ready for implementation planning.** The design has publication paths that bypass licensing and quality controls, an incomplete extraction/review state machine, and insufficient provenance for several displayed numbers and settlements. Review only; no files changed or tests run.

Severity: **P1** blocks implementation or violates the mandate; **P2** must fix before planning; **P3** optional improvement.

The initial RLS policies provide self-SELECT/self-INSERT, not general self-update/delete.
- **§2.2–3 — Holds.** Checked the stock page, `src/lib/data/mock.ts`, `src/lib/stocks/detail.ts`, consensus route, Tushare adapter and consensus derivation. Mock fallback is real. The adapter requests the named fields; “5000 points” is documented in repository comments, not independently established here.
- **§2.4 — Mostly holds.** Checked `src/lib/research/{sources,types}.ts`, `ingest/collectors/{edgar,cninfo,hkexnews,write}.ts` and `20260705000000_research_os_tables.sql`. Source immutability, URL versioning and permission/origin types are present. Hash uniqueness is **`(user_id, content_hash)`**, not global. `ingestSource` requires `ctx` and a nonempty `title`; §6.5’s sample omits both.
- **§2.5 — Holds for the resolver’s stated signature and tables.** `src/lib/entities/resolve.ts` accepts exactly one identifier plus options. It returns neither provenance nor a mapping generation. `20261105091000_issuers.sql` supplies classifications and separate issuer memberships.
- **§2.6 — Holds.** Checked `src/lib/dq/{batches,freshness,quarantine,rules}.ts` and `20261105090000_dq_foundation.sql`: six counters, the two existing information codes, event cadence, open-quarantine uniqueness and reconciliation schema are present. Calls to `startBatch` and `quarantine` require the client argument omitted from the spec’s examples.
- **§2.7–8 — Holds.** The quarantine route performs admin, Content-Type and Origin checks and audits resolution. `src/lib/admin/auth.ts` checks `profiles.role='admin'`. Its existing audit occurs after resolution, with audit failures logged.
- **§2.9 — Holds within searched application/script code.** The private bucket pattern and 52,428,800-byte limit appear in `20260715130000_security_master_data.sql`; no `createSignedUrl` call was found under `src` or `scripts`. That byte limit is **50 MiB**, not decimal 50 MB.
- **§2.10 — Partly false.** `src/lib/scoring/forward.ts` implements 5/20/60-bar returns, but its baseline is **on or after** the call date. `src/lib/analyst/score-store.ts` adds an important truncated-history guard absent from the proposed settlement contract.
- **§2.11 — Holds.** `resolvePlatformLlm`, registry JSON files and `ajv@8.20.0` exist; `package.json` declares no PDF parser. Resolving configuration does not itself provide metering, quota enforcement or persisted invocation evidence.
- **§2.12 — Holds narrowly.** `vercel.json` has six cron entries and region `hnd1`; the named securities-sync route uses timing-safe Bearer verification and `maxDuration=300`. That does not establish limits for the future extraction route.
- **§2.13–14 — Holds.** `scripts/ci/research-checks.ts` enforces exact critical-suite inventory; the latest lock entry is `20261105091000_issuers.sql`. Types are hand-maintained. Plan 2 remains a design dependency, not landed functionality.
- **§2.15–16 — Holds as repository evidence.** The message files/parity-test layout exists. `REPORT.md` and `PAGE_INVENTORY.csv` explicitly distinguish client-resource inspection from verified interaction. The 301-report figure comes from the mandate’s recorded observation.

Plan 1 §14 and plan 2’s transaction/replay contracts were checked; they do not supply the missing broker-specific guarantees above.

## Unsure

- **Supabase Storage deployment behavior:** No live Storage test was run. Current official documentation establishes that signed upload URLs are bearer capabilities valid for **two hours**; actual installed-version `upsert:false`, concurrent uploads, token reuse, MIME enforcement and post-purge URL behavior remain unverified. [Supabase documentation](https://supabase.com/docs/reference/javascript/storage-from-createsigneduploadurl)
- **Vercel/cache behavior:** Production plan limits, request/download memory limits and deployed CDN invalidation were not verified. The repository’s `maxDuration=300` is configuration evidence only. `revalidatePath` documents framework cache invalidation, not revocation of already cached browser responses. [Next.js documentation](https://nextjs.org/docs/app/api-reference/functions/revalidatePath)
- **PostgreSQL deployment equivalence:** Owner-rights views with anon SELECT are valid; `lag()` and expression indexes are not inherently infeasible. No proposed migration exists to execute, so actual ownership, complete grants, expression syntax, window ordering and PostgREST exposure remain untested.
- **Tushare:** Actual entitlement, foreign-broker coverage, upstream provenance and endpoint completeness were not verified externally. Repository types/comments are insufficient evidence of those service guarantees.
- **Licensing/F3/F4/F6:** No actual licence approvals or settled external interface contracts were supplied. The review therefore identifies required guarantees; it does not establish permission to publish or process any real report.
