| Severity | Section | Issue | Fix |
|---|---|---|---|
| **P1 · T1** | S §§4.3, 4.8 | **Restricted official values are copied into a publicly readable table.** `industry_valuations.official_value` is readable whenever the scheme is public and the cell published; its policy never checks `official:tushare-sw_daily`. Thus an official dataset marked `internal` remains directly queryable through the copied column, despite the drawer restriction. | Keep comparator values in service-only storage and expose them through the separately authorized projection. Test direct anonymous reads with scheme public and official internal. |
| **P1 · T2** | S §§4.3, 6.4 | **The moving recomputation boundary prevents routine activation.** Weekly runs use `today−400 days`, but activation requires `recompute_from` to be no later than the active run’s boundary. Every later weekly boundary fails; a full-history quarterly run also prevents subsequent rolling runs. The required valuation `inputs_watermark` is absent from its schema. | Use computation generation and explicit dependency freshness for obsolescence; treat `recompute_from` as coverage metadata, not chronological freshness. Define the required persisted fields. |
| **P1 · T3** | S §§4.3–4.5, 4.9, 5.2 | **Source resolution can declare success without usable memberships, and source corrections lack an applicable transition.** The spec writes `issuer_id` and then applies memberships through separate operations; if application fails, future resolution skips the now-non-null record and `n_unresolved` also excludes it. Separately, a corrected non-null `out_date` becomes current source evidence but §4.5 rejects the corresponding membership change. | Atomically commit resolution plus membership application; leave failures explicitly unresolved/pending. Define replacement of superseded memberships, including corrected dates, with keys and exclusion constraints that permit retained historical versions. |
| **P1 · T4** | S §4.3 | **The new aggregate-table policy cannot be implemented against its declared columns.** `industry_metrics` contains neither `scheme` nor `version`, while “dataset public” is defined using those columns. The active-run helper supplies only a boolean and cannot establish the dataset’s license. | Authorize via a helper that obtains scheme/version from the referenced run and checks both license and activity, or add consistently constrained scheme/version columns. |
| **P1 · T5** | S §§4.3, 6.1–6.2 | **Observation versioning cannot retain two different observations on the same day.** Marks and official values key versions by `observed_date`, yet changed values must insert a new version. A corrected response during a same-day retry collides with the primary key; overwriting would destroy evidence. | Use an observation UUID or sufficiently precise timestamp plus deterministic idempotency key; preserve both observations and explicitly link supersession. |
| **P1 · T6** | S §§5.3, 6.4 | **Valuation carry-forward ignores method compatibility.** All dates before the rolling boundary are copied into the new run without checking method, configuration, formula or comparator basis. After a methodology change, the active run can mix old and new definitions under one method declaration and calculate percentiles across them. | Require matching method/config/formula/comparator contracts for carry-forward; otherwise recompute the full affected history or keep separately identified series. Recompute series qualification and publication flags for the resulting snapshot. |
