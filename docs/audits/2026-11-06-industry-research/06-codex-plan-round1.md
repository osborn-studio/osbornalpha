| **P1** | **Task 18, Step 2** | **Stale-page fallback bypasses licence enforcement.** `loadView` caches public views, but its catch branch returns them after *any* subsequent error (**P:15623–15644**). This violates the licence gate and can exceed even the accepted one-day cache residue (**S:344–349**). | Permit stale data only after a successful current licence check for the relevant dataset; fail closed if that check fails. | **P1** | **Task 8, Step 7** | **Later delistings never close already-resolved memberships.** Both the runner and pure resolver restrict processing to unresolved source records (**P:7292**, **P:7357**). This is a demonstrated upstream behavior: **03-tushare-verification.md:48** reports 341 delisted stocks still having open source windows. | Reconcile delisting bounds for already-resolved current sources, preserving their stored issuer identity. Close open memberships through the controlled write path; version corrections where necessary. Add a two-run test: listed first, delisted later, identical membership payload. |
| **P1** | **Task 11, Step 3**; Task 2, Step 2 | **GC can delete a manifest that a new run has reused.** GC selects candidates, deletes bucket objects, then rechecks references when deleting index rows (**P:9038–9044**, **P:3488–3513**). Between selection and removal, another worker can reuse the hash, refresh its index timestamp and stage references. GC then removes the blob; the final SQL check preserves the index/reference but cannot restore the object. The 24-hour grace period does not prevent this interleaving. | Add a GC claim/tombstone protocol coordinated with manifest registration and staging, preventing attachment while deletion is underway and requiring re-upload afterward. Test the exact interleaving: candidate selected → hash reused and referenced → deletion attempted. |
| **P2** | **Task 2, Step 2**; Task 8, Step 7 | **Membership successors are matched only by level, losing source lineage.** The `succ` CTE selects the first target of the old row’s level (**P:2925–2933**). | **P2** | **Task 9, Step 8** | **SIC leases do not exclude concurrent workers.** The claim predicate checks `next_due_at`, but the update changes only lease fields (**P:7889**).
