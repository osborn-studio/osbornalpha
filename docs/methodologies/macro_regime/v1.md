# macro_regime@v1 · 宏观象限（当期 nowcast）

> 状态：**active**。真实 MacroReadApi.classifyAsOf 已复用发布管线的 buildRegimeInput + classifyRegime；上游版本仍为 v1.0。生产装配仅在 MACRO_JUDGMENTS_ENABLED 为 1 / true 时启用。
> `publishable=false`：本方法可达的 origin 键（`macro_observation×macro_workbench`、`macro_snapshot×macro_workbench`）在 `docs/methodologies/licenses.json` 里都是 `unverified`，owner 确认许可前读接口不返回本方法的卡片（规格 §4.1、§17；许可表不进 `formula_hash`，决策 D3）。

## 1 回答什么问题

"截至 `as_of`（日期）可见的宏观观测，判定区域 `US` / `CN` 在**参考期 = `as_of` 所在月**处于美林时钟四象限中的哪一个？"这是**当期 nowcast**，不是对未来状态的预测：判断说的是"用当时能看到的数据，2026-09 处于复苏"，而检验它的是"数据补全与修订之后，同一个分类函数对 2026-09 是否仍给出复苏"。它检验时效与修订风险；**不**检验资产表现（那是 `macro_regime_asset_pair`，未实现，规格 §11.1、§18.1），也**不**检验 3 个月后的状态。

## 2 主体与输入

主体：`{type:'macro_region', key:'US'|'CN'}`。生产者绑定：`binding = {snapshot_id}`（宏观 WP-M3 发布的一个快照；同区域同日两个快照 = 两条不同判断，规格 §6.4）。

| `kind` | 来源 | 冻结的投影 | `available_at` | `origin`（`src/lib/judgments/origins.ts`） |
|---|---|---|---|---|
| `macro_snapshot` | `MacroReadApi.snapshot(snapshot_id)`（将来：anon 读 `macro_snapshots` ⋈ `macro_regime_results`） | `snapshot_id, region, as_of, methodology_version, catalog_version, observation_ids, primary_state, secondary_state, scores, norm, coverage, margin_pp, growth_axis, inflation_axis` | 其 `observation_ids` 各观测 `available_at` 的**最大值**（不是快照 `created_at`，规格 §3.7） | `macro_snapshot × macro` |
| `macro_observation`（每个 `observation_id` 一条） | `MacroReadApi.observation(id)`（将来：anon 读 `macro_observations where status='ok'`） | `series_id, period_end, value, unit, vintage_id, available_at` | 观测自身的 `available_at` | `macro_observation × macro` |

登记校验 `max(available_at) ≤ as_of 23:59:59.999Z`（否则 `lookahead`）。目录是 `src/lib/macro/catalog.ts` 的版本化代码，没有系统时间戳，不能作为 P1-08 的 `table_rows` 输入。目录与规则由方法 deps / import closure 纳入 `formula_hash`；绑定快照的 `catalog_version` 必须等于本方法固定的 `params.catalog_version`，并冻结在 claim 中。版本不符 → `upstream_version_mismatch`（保留绑定快照，D1）。仅 `active` / `superseded` 快照可绑定；其它状态 → `snapshot_not_published`，可构造时保留绑定输入。

## 3 公式与参数

分类函数**不在 F4 里**：它就是宏观规格 §5 的 `regime.ts`（v1.0 规则表 §5.2、输出公式 §5.3），F4 只把快照的结果重述为一条类别型主张：

```
selected               = snapshot.primary_state
classes                = [recovery, overheat, stagflation, recession]
distribution           = snapshot.norm                       (score[s] / Σ score；不是概率)
scores_are_not_probabilities = true
margin_pp              = round((norm[primary] − norm[secondary]) × 100, 6)   百分点（规格 §8.1 G28）
catalog_version        = snapshot.catalog_version
```

`macro_regime@v1` 将可接受的目录版本固定为 `params.catalog_version = 'macro-catalog/30bcaa2a33c5'`。此值取自本次合并树的 `CATALOG_VERSION`，不是运行时读取的当前目录版本；目录新增序列也不会改变 v1 对已绑定快照的判定。新目录版本需要 `macro_regime@v2`。

单位核对：快照必须包含四个类别的有限 scores / norm、非负且总和在 1 ± 1e-9 内的 norm、属于四类且互异的主 / 次判定，以及有限 `margin_pp`，否则 `invalid_snapshot`。若 `margin_pp` 与上式差 > 0.01 个百分点（例如宏观侧误存为比例 0.0909），弃权 `margin_unit_mismatch`。

| 参数 | 值 | 来源 |
|---|---|---|
| `grace_days` | 30 | 规格 §3.4：`calendar_months` 类一个月度发布周期（政策常量） |
| `label_policy` | `cutoff_vintage` | 规格 §3.4：宏观修订频繁，只在 `settle_by` 当天用当时可见的 vintage 结算 |
| `threshold_n` | 100 | 规格 §8.4 / owner 决策 O2 默认（运营门槛，不是统计保证） |
| `ece_max` | 0.10 | 同上（categorical 不用 ECE 门控，只写进校准行） |
| `window_years` | 3 | 规格 §8.2 默认；≥ 期限 3 个月的 3 倍 |
| `embargo_days` | 0 | 规格 §8.2 默认 |
| `catalog_version` | `macro-catalog/30bcaa2a33c5` | v1 固定接受的上游目录版本 |
| `horizon` | `{calendar_months, 3}` | 规格 §11.1：给迟到发布与修订留 3 个月，取宏观规格 §5.2 Δ(3M) 的同一时间尺度 |

## 4 可证伪条件、目标期与标签政策

```
condition = { resolver: 'macro_regime_replay',
              params: { region, reference_period: as_of 所在月 (YYYY-MM), macro_methodology_version: 'v1.0', catalog_version },
              predicate: { op: 'eq', rhs: selected } }
target    = { kind: 'period', period: reference_period + 3 个月 }
settle_after = target 月末 + 1 天（00:00:00.000Z）；settle_by = settle_after + 30 天
label_policy = cutoff_vintage
```

算例：`as_of 2026-09-11` → `reference_period 2026-09` → `target 2026-12` → `settle_after 2027-01-01T00:00:00.000Z`、`settle_by 2027-01-31T00:00:00.000Z`。条件文案（中文）：`US 2026-09 当期象限为“复苏”（同一分类函数在截止 vintage 下对同一参考期重算）`。

## 5 结算 resolver 与实现值定义

`macro_regime_replay`（`src/lib/judgments/resolvers/macro.ts`，进本方法 `deps`）：在 `cutoff = settle_by` 调 `MacroReadApi.classifyAsOf(region, reference_period, cutoff, 'v1.0')`——**同一个** `regime.ts` 函数（同版本规则表、同 `catalog_version` 权重、同 argmax），输入换成"`period_end ≤ reference_period` 月末且 `available_at ≤ cutoff` 的最新 vintage"。实现值 = 重算的 `primary_state`；`hit ⇔ 实现值 = selected`。`label_available_at` = 所用观测 `available_at` 的最大值；证据 `{observation_refs: [{series_id, period_end, vintage_id, value, available_at}], catalog: {version, weights, rules_version}, regime_result}`。重算时 `coverage < 0.6` → `Unavailable(coverage)` → 到 `settle_by` 后 `void(no_data:coverage)`。混频（CN GDP 季度）、未匹配规则、缺失观测的处理完全沿用 `regime.ts`，F4 不另写轴规则。

夹具算例：同 vintage → `recovery` → 命中；9 月数据到齐（DGS10 Δ(3M) +30bp、CPI 3.1、ISM 49.2、PPI 2.7、VIX 19.5）→ 得分 12.5 / 24.5 / 19 / 10 → `overheat` → 未命中（`fixtures/judgments/macro/us-2026-09-revised.json`）。

## 6 不适用情形（何时 abstain）

| 情形 | 结果 |
|---|---|
| 没有 `binding.snapshot_id` | 弃权 `binding_missing`（无输入） |
| 快照的区域或 `as_of` 与主体 / 工作项不符 | 弃权 `binding_mismatch`（保留可构造的绑定快照） |
| 快照 `methodology_version ≠ 'v1.0'` 或目录版本不符 | 弃权 `upstream_version_mismatch`（只冻结快照一条输入）；需要登记新的 F4 方法版本 |
| 快照不满足 §3 不变量 | 弃权 `invalid_snapshot` |
| 快照不是 active / superseded | 弃权 `snapshot_not_published`（D1 保留可构造的绑定输入） |
| 快照 `coverage < 0.6` | 弃权 `coverage_below_threshold`（正常情况下这种快照是 `failed`，不会被发布） |
| 快照引用的观测读不到 | 弃权 `observation_missing`（`missing` = 观测 id） |
| `margin_pp` 单位不符 | 弃权 `margin_unit_mismatch` |
| 任一输入不在公共读路径（隔离、不公开） | 登记拒绝 `input_not_public`（不是弃权） |

### 与已提交宏观工作台的适配

上述 0.8 coverage 算例是保留的合成夹具（fixtureMacroReadApi），不是当前生产目录的输出。生产目录中 ISM 为 missing、VIX 为 restricted，分类器不计其贡献；norm 舍入至 6 位，百分点检查允许 0.01pp 误差。
T19 review fixes 决策：真实 seriesCatalog 没有 created_at / updated_at，移除目录 table_rows 输入；以代码依赖哈希覆盖目录和规则，并核对绑定快照的固定目录版本。保留 active 状态和合成算例，更新夹具版本标识；合成算例不是生产目录分类输出。新增发布状态与数值不变量检查，重建黄金回放。本轮是未发布实施修复；已登记的 formula_hash 若不同，仍须按版本规则处理，不绕过同步漂移检查。

绑定不符或观测缺失的 gather 弃权也保留可构造的绑定快照（D1）；快照不可读或未分类时无输入。
