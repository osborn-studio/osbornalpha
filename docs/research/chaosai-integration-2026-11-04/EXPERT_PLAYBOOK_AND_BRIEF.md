# 行业研究 · 公司研究 · 外资研报：顶尖架构师会怎么做，以及重写后的题目

日期：2026-11-04
范围：ChaosAI 四个核心页面中尚未设计的三个——`/industries`（行业研究）、`/company` + `/monitor`（公司研究与跟踪）、`/foreign-research`（外资研报）。`/macro-strategy` 已有规格（`docs/superpowers/specs/2026-11-04-macro-workbench-design.md`）。
前置材料：`REPORT.md`（全站研究）、`MACRO_STRATEGY_DEEP_DIVE.md`（宏观页实证）、`SOURCE_MAP.csv`。

本文回答五个问题：顶尖的人会怎么设计系统；他们会做哪些你没要求的事；他们从哪些原始素材入手；用什么方法和工具；除了你和我，还有什么能证明结果正确。最后给出重写后的题目。

---

## 0. 先说三条总原则（三个板块共用）

1. **原始素材优先，整理稿只作对照。** 对方网站、Codex 报告、本文都是"二手"。顶尖团队从披露文件、指数公司、统计局、交易所接口入手，把对方页面只当作"功能参考 + 回归测试的对照样本"。
2. **每个数字都要能回放。** 任何页面上的值都能回答：来自哪份原始文件的哪一行、何时可得（available_at）、经过什么变换、哪个代码版本算出来的。做不到回放的数字不上线。
3. **判断与事实分层。** 财报数字是事实；"生命周期阶段""胜率""值博率""评级"是判断。判断必须带方法版本、输入快照、可证伪条件，并被持续打分（校准），否则只是文案。

## 1. 行业研究（`/industries`）

### 1.1 对方做了什么（实证）

六个模块：申万一级 31 行业 × 10 年年度 + 14 季财务热力图（营收/归母同比、毛利率、ROE）；6 阶段生命周期分布（三段 3 年 CAGR a/b/c 判定 + 宏观定性修正）；10 行业 5 维景气雷达（估值维度 50 占位、现金流用利润增速代理）；PE/PB/PS 11 年分位（申万指数周频）；PB+PS 均值阈值 30/70 的高估/低估结论；9 行业组 × 6 阶段的 88 个细分行业矩阵 + Gartner 曲线；6 阶段选股模型表；106 篇子行业报告索引。来源标注"恒生聚源 / 申万指数周频 xlsx"。

### 1.2 顶尖架构师会怎么设计

```
原始披露 (XBRL/PDF)  ──► 公司级财务事实库 (point-in-time, 含重述)
行业分类标准 (申万/GICS 版本化) ──► 历史成分表 (valid_from/to)
指数公司估值 (申万/中证官方 PE/PB/PS) ──► 估值事实库
                 │
                 ▼
   行业聚合引擎 (整体法 / 中位数法 / 可切换，metric_version)
                 │
                 ▼
   派生判断层：生命周期分类器 v1 · 景气评分 v1 · 估值分位 v1
                 │
                 ▼
   快照发布 (industry_snapshot_id) ──► 页面 ──► 来源抽屉 / 回放
```

关键设计决定：

- **成分表是一等公民。** 行业指标必须用"当时的成分股"计算，否则 2016 年的行业毛利率会被今天的龙头污染（幸存者偏差 + 前视偏差）。表 `industry_memberships(company_id, industry_id, classification_version, valid_from, valid_to)`。
- **聚合方法显式化。** 行业毛利率 = Σ毛利 / Σ营收（整体法），而不是公司毛利率平均；ROE 用 Σ净利 / Σ净资产；金融业单独口径。方法名和版本进入每个数字的元数据。
- **判断层可替换、可回测。** 生命周期分类器输入是三段 CAGR + 渗透率 + 资本开支/折旧比等，输出阶段 + 置信区间；阈值在 `methodology_version` 下版本化；每季度重跑并记录"阶段迁移"。
- **缺失就是缺失。** 不用 50 占位，不用利润增速代理现金流。缺数据的维度在雷达图上显示为缺口并说明。
- **细分行业用标签图而不是固定 9 组。** 一家公司可以同时属于"光模块"和"AI 算力产业链"；用 `industry_tags(company_id, tag, source, confidence, valid_from)` 多对多，再按标签聚合。

### 1.3 他们会做但你没要求的事

- 建立**行业分类版本表**（申万 2014 / 2021 版；GICS 年度调整），并写迁移对照。
- 把每个行业指标做**与官方发布值的对账**：例如申万指数公司公开的行业 PE/PB 与自算值的偏差必须 < 1%，否则不发布。
- **单季差分一致性检查**：Q4 单季 = 年报 − 三季报累计，用同一版本财报；重述后重新差分并保留旧版本。
- 为"生命周期阶段"写**可证伪定义**和**历史回测**：2016 年判定为"成长中期"的行业，之后 3 年营收 CAGR 是否真的落在 25–50% 区间；给出混淆矩阵。
- 把**产业链上下游**建成图（供应商/客户关系来自年报前五大客户/供应商披露、招股书），而不是人工列的"上中下游"。
- **替代数据交叉验证**行业景气：出口分项（海关 HS 编码）、乘联会/中汽协月度产销、SEMI/SIA 半导体出货、国家统计局分行业工业增加值与 PPI 分项、上市公司招聘岗位数（第三方）。
- 建**同行业跨市场对比**（A/H/US 同业），统一会计准则差异标注（CAS vs IFRS vs US GAAP）。

### 1.4 原始素材

| 素材 | 入口 | 用途 |
|---|---|---|
| A 股定期报告 XBRL | 巨潮资讯（cninfo）披露接口；沪深交易所 XBRL 文件 | 公司级财务事实（营收、毛利、净利、净资产、经营现金流、资本开支） |
| 港股年报/中报 PDF | HKEXnews 披露易 | 同上（需 PDF 表格抽取） |
| 美股 10-K/10-Q XBRL | SEC EDGAR `companyfacts` / `frames` API | 同上，结构化、免费、含历史 |
| 行业分类标准 | 申万宏源研究所《申万行业分类标准（2021 版）》；中证/GICS 分类表 | 分类版本 + 成分历史 |
| 行业指数估值 | 申万指数官网 / 中证指数公司 日度 PE/PB/股息率 | 估值事实 + 对账基准 |
| 宏观分行业 | 国家统计局（工业增加值、分行业 PPI、固定资产投资分行业）、海关总署（HS 编码出口） | 景气交叉验证 |
| 行业协会 | 乘联会、中汽协、中国光伏行业协会、SEMI、SIA、CINNO 等月报 | 高频景气 |
| 产业链关系 | 年报"前五大客户/供应商"、招股书"主要客户/供应商" | 供应链图谱 |
| 对方页面 | `/industries` 的 31 × 10 热力图 | 仅作回归对照样本，不做数据源 |

### 1.5 方法与工具

- 采集：EDGAR API（免费、带 User-Agent）、cninfo 公告接口 + Arelle / python-xbrl 解析 XBRL、HKEXnews 列表 + Docling / MinerU 做 PDF 版面与表格抽取；AKShare / Tushare / BaoStock 作为 A 股财务的第二来源做交叉对账。
- 存储与计算：Postgres（现有 Supabase）+ DuckDB 做离线聚合；dbt 管理派生表与测试；所有派生指标有 `metric_version`。
- 数据质量：pandera 或 Great Expectations 写约束（毛利 ≤ 营收、净资产 > 0 除非标注、同比在 [-100%, +1000%] 外隔离）；跨来源容差对账（XBRL vs Tushare 差异 > 0.5% 隔离）。
- 判断层：生命周期分类器用显式规则 + 版本；景气评分用 0–100 分位标准化并输出每维来源；回测用 point-in-time 数据，评估指标（混淆矩阵、阶段迁移命中率）。
- 可视化：热力图/雷达/分位条用内联 SVG（规格里已定）；表格等价视图。

### 1.6 独立验证（除你我之外）

- **官方对账**：行业 PE/PB/PS 与申万指数公司、中证指数公司公布值逐日对账；公司财务与 EDGAR companyfacts / cninfo XBRL 原值逐项对账。
- **双来源一致性**：XBRL 与 Tushare/AKShare 同字段容差内一致，差异自动进隔离队列。
- **会计恒等式属性测试**：毛利 = 营收 − 营业成本；ROE 与净利/净资产的派生一致；单季差分可逆。
- **历史回放测试**：用 2023-06-30 的 `available_at` 回放行业快照，与当时保存的快照逐格一致。
- **对方页面作为回归样本**：31 × 10 热力图逐格对比，差异逐项解释（成分/口径/重述），不要求一致但要求可解释。
- **第三方模型复审**：按仓库惯例交 Codex 做审计轮次（见记忆中的"Codex review-round convention"）；审计报告落 `docs/audits/<date>-industry-data/`。
- **领域专家抽样**：请一位卖方行业分析师抽 3 个行业、各 5 个季度的数字做人工核对，记录在 `verification.json`。

## 2. 公司研究与跟踪（`/company` + `/monitor`）

### 2.1 对方做了什么（实证）

231 家覆盖（港 70 / A 129 / 美 32），每家：值博率星级、核心逻辑一句话、覆盖时价格、胜率、预期涨幅、下跌空间、赔率、凯利仓位、研究日期、DCF 勾选；行业树二级筛选；季度上调/下调标记；数据来源是一份内部 Markdown 总览 + 各家深度报告。`/monitor` 跟踪 25 家：核心跟踪指标（目标标准 / 实际 / 置信度变化 / 权重）、机构评级表、业绩说明会纪要、跟踪事件（超/低于预期）、胜率/赔率/凯利 before→after、下次跟踪节点。

### 2.2 顶尖架构师会怎么设计

```
披露事实库 (财报 XBRL · 公告 · 业绩会纪要 · 卖方共识)
        │
        ▼
论点账本 Thesis Ledger (可证伪论点 · 检查点 · 触发条件 · 版本)
        │
        ▼
预测登记 Forecast Registry (每个"胜率/目标价/下次验证"带时间戳与分布)
        │
        ▼
结算引擎 Settlement (到期自动对照实际 → Brier / 命中率 / 校准曲线)
        │
        ▼
仓位建议 (分数凯利 · 用登记的分布而不是点估计)
        │
        ▼
页面 (公司卡 · 跟踪时间线 · 校准看板) + 来源抽屉
```

关键设计决定：

- **"胜率"不是感觉，是登记过的预测。** 每一次"胜率 82%"都是一条 `forecasts(entity, claim, p, horizon, registered_at, settles_at)`；到期用事实结算，累计得到个人/模型的 Brier 分数与可靠性曲线。没有结算机制的胜率不显示为百分比，只显示"研究员信心（未校准）"。
- **论点可证伪。** 每条核心逻辑必须写成"若 Q4 单季毛利率 < 23% 则论点失效"这种形式；系统在财报发布后自动比对并改状态。
- **卖方评级来自授权源或公开 IR 共识页**，不从新闻稿抄；每条评级带机构、日期、币种、报告时价格。
- **凯利仓位用分布而非点估计。** 输入是登记的上行/下行情景与概率，输出分数凯利（¼–½ Kelly），并显示对假设的敏感性。
- **复用 OsbornAlpha 已有的 thesis / signals / monitor / portfolio 模块**，不建第二套。

### 2.3 他们会做但你没要求的事

- **预测可追责**：所有研究员/模型的历史预测与结算结果公开在"校准看板"，这是对方完全没有的。
- **业绩会纪要走原始录音/文字稿**（上证 e 互动、深交所互动易、HKEX 网络直播、公司 IR 页），LLM 摘要必须附时间戳或页码引用。
- **事件驱动重评**：财报、评级变动、大股东减持、回购、指引修改触发论点重算，而不是等人工跟踪。
- **同业横向对比自动化**：同行业的毛利率/增速/估值分位放在同一张表，避免孤立判断。
- **做空/反方论点强制字段**：每家公司必须有"最强反方论据"和"什么会让我改变看法"。
- **法规与合规**：研究观点的免责声明、不构成投资建议、持仓披露；对外开放前需明确。

### 2.4 原始素材

| 素材 | 入口 |
|---|---|
| 财报与公告 | EDGAR（10-K/10-Q/8-K/业绩会 8-K 附件）、cninfo、HKEXnews；仓库已有 `src/lib/research/ingest/collectors/`（EDGAR、巨潮、HKEX） |
| 业绩说明会 | 公司 IR 网站 webcast / transcript、上证 e 互动、深交所互动易、HKEX 业绩发布会录像 |
| 卖方评级与目标价 | 授权终端（Wind/Bloomberg/Refinitiv）或公司 IR 页 analyst coverage；对方页面的评级表不可作为来源 |
| 股权与交易 | 交易所大股东增减持公告、回购公告、港交所权益披露（DI） |
| 价格 | 现有 DataGateway / 行情适配（用于覆盖时价格、结算） |
| 替代数据 | 招聘岗位、App 下载/MAU（第三方授权）、海关分企业出口（授权） |

### 2.5 方法与工具

- 结构化抽取：LLM 抽取 + 引用跨度（页码/时间戳）+ JSON Schema（ajv，仓库已有）校验；抽取质量用 30–50 份人工标注的黄金集算 precision/recall。
- 预测登记与结算：`forecasts` / `settlements` 表 + Brier 分数、可靠性曲线（分桶 0.1）、Log score；季度校准报告。
- 估值：DCF 用蒙特卡洛（WACC、g、利润率分布）输出区间，不输出单点目标价；敏感性表自动生成。
- 事件管道：复用 `research_signals` / `monitor.ts`，新增披露事件 → 论点重评任务。
- 评测：LLM 摘要用 Inspect / promptfoo 一类的 eval harness，固定夹具 + 回归。

### 2.6 独立验证

- **结算即验证**：胜率在时间里被事实打分；6 个月后公布 Brier 分数，这是对"判断质量"唯一客观的证明。
- **数字对账**：卡片上的营收/毛利率与 XBRL 原值一致（自动）。
- **引用可点击**：每条摘要句子能跳到原文页码/时间戳；随机抽样 5% 人工核对引用是否支撑结论。
- **双模型对照**：同一份财报让两个不同模型独立抽取，字段不一致进复核队列。
- **外部基准**：目标价区间与卖方共识区间的偏离度统计；不是要一致，而是要能解释。
- **审计轮次**：Codex / 第三方模型审计 + 领域专家抽样，报告入 `docs/audits/`。

## 3. 外资研报（`/foreign-research`）

### 3.1 对方做了什么（实证）

301 篇外资投行报告（高盛、摩根士丹利、摩根大通、Bernstein、汇丰、Guggenheim 等）的"一页纸"：机构、行业、评级（OW / MIXED / N/A）、中英标题、当前价 / 目标价 / 空间、报告定位、核心结论、方法论（WACC、g、终值占比）、风险与边界、标的代码与日期；按科技/消费/医药/宏观&策略分类计数。

### 3.2 顶尖架构师会怎么设计

```
原始 PDF (用户合法持有) ──► 文件哈希 · 元数据 · 私有对象存储（永不对外分发原文）
        │
        ▼
版面解析 (Docling / MinerU) ──► 文本块 + 表格 + 页码坐标
        │
        ▼
结构化抽取 (schema: 机构/分析师/评级/目标价/报告时价/币种/估值方法/关键假设/风险/催化剂)
        │  每个字段带 page + bbox 引用
        ▼
实体归一 (OpenFIGI / ISIN · A/H/US 多代码映射) + 去重 (simhash)
        │
        ▼
算术与一致性校验 (空间 = 目标价/现价 − 1 · 币种一致 · 日期 ≤ 入库日)
        │
        ▼
分析师追踪 (评级变动序列 · 目标价 vs 后验收益 · 命中率)
        │
        ▼
页面：一页纸（引用可点） · 机构/分析师看板 · 与公司研究联动
```

关键设计决定：

- **许可先行。** 研报原文受版权和分发限制（多数首页印有"不得向中国大陆投资者分发"等条款）。系统只对外展示元数据、独立撰写的摘要、以及引用片段；原文只在用户私有空间。这一条决定了产品形态，必须先于功能。
- **抽取带坐标。** 每个字段记录 `page, bbox, text_span`；一页纸上的每个数字可点击跳回原文位置。
- **机构与分析师是实体。** 建 `institutions`、`analysts`、`ratings_history`；可以回答"高盛过去两年对宁德时代的目标价轨迹"和"这位分析师的目标价命中率"。
- **与公司研究联动**：研报里的评级 / 目标价自动进入公司卡的"卖方共识"栏，来源指向该报告。

### 3.3 他们会做但你没要求的事

- **分析师准确率追踪**（研报发布后 3/6/12 个月的相对收益），把"外资说了什么"变成"外资说得准不准"。
- **跨机构分歧图**：同一标的不同机构目标价的分布与演变，比单篇摘要更有信息量。
- **假设提取与对比**：把报告里的 WACC、永续增长率、终值占比、产能/份额假设结构化，横向比较同一公司不同机构的假设差异。
- **报告与事实对账**：报告引用的财务数字与 XBRL 原值自动比对，标出不一致（对方的一页纸里已经出现"正文 9.8% 图表 9.6%"这种口径不一致，系统应自动发现）。
- **去重与版本**：同一报告的更新版、翻译版、摘录版用哈希与标题相似度归并。
- **合规日志**：谁上传、谁查看、是否导出，满足授权条款。

### 3.4 原始素材

| 素材 | 说明 |
|---|---|
| 研报 PDF 原件 | 必须是用户合法持有（终端订阅、机构授权）；对方网站的一页纸不是来源 |
| 报告引用的披露文件 | EDGAR / cninfo / HKEXnews，用于对账 |
| 证券主数据 | OpenFIGI（免费 API）、ISIN、交易所代码表，用于多市场代码归一 |
| 价格 | 现有行情链路，用于"报告时价格"核验与后验收益 |
| 机构披露页 | 投行研究披露/评级定义页（用于评级体系映射：OW/EW/UW、买入/中性/卖出、Outperform 等） |

### 3.5 方法与工具

- PDF 解析：Docling 或 MinerU（版面 + 表格 + 公式），pdfplumber / Camelot 作表格兜底；扫描件用 OCR（PaddleOCR）。
- 抽取：LLM + JSON Schema + 引用跨度；黄金集 30 篇人工标注，报告字段级 precision/recall ≥ 0.95 才上线。
- 实体：OpenFIGI 映射；评级体系映射表版本化。
- 去重：simhash / MinHash + 标题相似度。
- 存储：原文在私有对象存储（现有 Supabase Storage 私有桶），元数据与抽取结果入 Postgres，复用 `research_sources` 的 hash / version / permission 模型。
- 追踪：评级/目标价时间序列 + 后验收益计算（复用行情链路）。

### 3.6 独立验证

- **算术校验**：空间 = 目标价 / 现价 − 1（容差 0.5%）；币种与市场一致；目标价日期 ≤ 入库日期。
- **原文回溯**：随机抽样字段，点击引用必须落在原文对应位置（自动截图 + 人工抽查）。
- **黄金集评测**：字段级 precision / recall 持续监控，低于阈值阻断发布。
- **与公司事实对账**：报告中引用的财务数字与 XBRL 原值差异列表。
- **后验收益**：分析师/机构命中率是外部世界给出的证明。
- **合规审查**：法务或授权方确认展示范围；审计报告入 `docs/audits/`。

## 5. 重写后的题目（可直接作为新会话的开场 prompt）

> **目标**
> 以 osbornalpha.com 现有工程基础（Next.js 15 / Supabase / 现有研究来源库、采集器、行情适配、LLM 计量、UI tokens）为底座，独立重建 ChaosAI 四个核心页面的能力：宏观策略（已有规格）、行业研究、公司研究与跟踪、外资研报。目标不是复制页面，而是建立"原始披露 → 可回放的事实库 → 版本化的判断层 → 可验证的页面"这条链。
>
> **约束**
> 1. 数据只从原始来源建立：交易所/监管披露（EDGAR、cninfo、HKEXnews XBRL/PDF）、指数公司（申万/中证官方估值）、统计局/海关/行业协会、授权终端；AKShare/Tushare 仅作适配器并记录上游。对方网站的数据、评分、结论一律不导入，只作功能参考和回归对照样本。
> 2. 每个展示数字必须可回放：来源文件、行号/页码、`available_at`、变换、代码版本。做不到的不上线。
> 3. 事实与判断分层：财务数字是事实；生命周期阶段、胜率、值博率、评级是判断，必须有 `methodology_version`、输入快照、可证伪条件，并被结算与校准（Brier 分数、可靠性曲线）。没有结算机制的"胜率"不得显示为百分比。
> 4. 缺失就是缺失：不用占位值、不用代理指标冒充；行业指标用当时成分股计算（point-in-time），聚合方法显式。
> 5. 外资研报：原文只存用户私有空间，对外仅展示元数据、独立摘要和引用片段；许可与分发条款先于功能确认。
> 6. UI 遵守 `DESIGN.md` 与 `globals.css` tokens；中英双语；所有图表有表格等价视图。
>
> **每个板块都要交付**
> - 数据契约（catalog、来源、频率、口径、许可范围）与迁移。
> - 采集与校验管道（约束测试、跨来源对账、隔离队列、新鲜度）。
> - 判断层的版本化实现与历史回放。
> - 页面 + 来源抽屉 + 与其他板块的联动（宏观→行业→公司→研报）。
> - 独立验证证据：官方对账结果、双来源一致性、黄金集评测分数、历史回放一致性、第三方模型审计报告（`docs/audits/`）、领域专家抽样记录。
>
> **顺序**
> 先共用底座（实体主数据、披露事实库、文档管道、判断层框架、数据质量、评测），再按"行业研究 → 公司研究与跟踪 → 外资研报"推进，每个板块一份规格、一份计划、一轮审计。
>
> **明确不做**
> 导入对方数据；把判断包装成概率；把研报原文对外分发；为凑数量引入未经验证的指标。
