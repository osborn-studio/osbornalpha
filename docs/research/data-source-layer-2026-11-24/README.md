# 统一数据源接入层：方案

日期：2026-11-24　状态：待负责人决定，未开工

调查依据：对代码的只读盘点（检出点 `a5868e93`，比当前 `main` 旧几个合并；#316 之后分析师评分的日线来源可能已变，动工前需复核）。

## 1. 结论

现在没有统一的接入层。同一个供应商有多套客户端，数据源的选择散落在代码、环境变量和各模块里，管理页上看不到也改不了。

可以做，但“选数据源”对三类数据含义不同，不能用一个开关解决：

| 类别 | 包含 | “切换数据源”的含义 | 风险 |
|---|---|---|---|
| A 实时、不入库 | 报价、分时、图表 K 线 | 运行时改主源和回退顺序 | 低 |
| B 入库、可重放 | 财务事实、行业、宏观、文档、实体 | 不是切换，是**并列接入第二个源**，各自入库、互相对账，再选哪一个用于展示 | 中 |
| C 判断的冻结输入 | 判断用的价格等 | 不可切换；数据源是公式哈希的一部分，换源等于发新方法版本 | 高，本方案只展示不改 |

## 2. 现状要点

- **路由不一致**：报价把 DataGateway 排第一，日线却排最后（它的日线只有收盘价，开高低是合成的）；后复权只有东方财富一个源。
- **多处绕过路由**：观点页、简报、回测、组合复盘、分析师评分直接调东方财富。
- **客户端重复**：Tushare 三套，SEC submissions 四套，EDGAR / 巨潮 / 披露易文档各两条流水线，限速器互不相通。
- **来源记录有缺口**：报价和 K 线从不入库；`recommendations`、`recommendation_scores`、`industry_security_delistings` 没有来源列。分析师评分的基准收盘价每次刷新都重新从东方财富读，换供应商会悄悄改变分数。
- **新增供应商要改库**：`filings.source`、`disclosure_documents.source`、`macro_evidence_objects.adapter` 等是数据库里写死的枚举。
- **审计登记不全**：数据集登记表缺宏观、行业、文档、港股事实等；证券主数据用自己的运行表。
- **许可分三处**：行业在数据库表（只有接口，没有页面），判断在仓库文件，宏观在目录字段。
- **开关全是环境变量**，没有数据库配置表；`FACTS_CN_ENABLED` 在不同模块里含义还不一样。

可复用的现成部件：K 线可靠性引擎（熔断、并发上限、预算、回退一致性检查）、请求节流器、内容寻址的原始数据存储、批次回执、对账对、行业许可开关（闭集 + 只能经函数写 + 同事务写审计日志）。

## 3. 设计

### 3.1 来源目录（代码里，单一事实来源）

一份目录列出每个供应商及其能力：支持的数据类别、市场、复权方式、许可状态、凭据的环境变量名、限速参数。

- 每个供应商只保留一个客户端，共用限速器和熔断器。
- 能力表负责拦住无效选择，例如不允许把 DataGateway 设成日线主源、不允许把非东方财富设成后复权源。
- 凭据仍只在环境变量里，目录只记变量名。

### 3.2 路由配置（数据库里，可在管理页改）

新表，按“数据类别 × 市场”保存有序的来源列表和启用状态。

- 沿用行业许可开关的模式：闭集校验、只能经函数写、同事务写审计日志、写后失效缓存。
- 代码里的默认值等于今天的行为；表里没有记录时行为不变。
- A 类：可改主源和回退顺序。
- B 类：只能在“已入库并通过对账的数据集”之间选展示用哪一个，不触发重算，不改历史。
- C 类：只读展示。

### 3.3 来源留痕

- 补齐缺失的来源列。
- 被存下来的计算所用到的价格（如评分基准价）要把实际命中的来源和取数时间一起存下。
- 报价和图表不入库，但把每次请求的来源尝试结果按来源汇总成健康指标保存。

### 3.4 管理页 `/admin/sources`

每个数据类别一行：当前主源和回退顺序、各来源健康状况（成功率、超时、熔断状态、新鲜度）、许可状态、最近的变更记录。界面先在 Claude Design 画布上设计。

### 3.5 审计登记补全

所有数据集进同一张登记表，并增加“来源”字段；三处许可合成一个只读视图（先不迁移存储）。

## 4. 分期

| 期 | 内容 | 行为变化 | 规模（粗估） |
|---|---|---|---|
| P0 | 来源目录；合并重复客户端和限速器；补全数据集登记；只读管理页 | 无 | 4–5 个 PR |
| P1 | A 类路由表；让绕过路由的调用方改走路由；来源健康指标 | 仅在管理员改配置时 | 3–4 个 PR，1 个迁移 |
| P2 | 来源留痕补缺（评分基准价、退市表等） | 无（新增列） | 2–3 个 PR，1–2 个迁移 |
| P3 | B 类并列多源：恒生聚源作为第一个接入者，与 Tushare 申万数据建对账对，提供展示主源选择 | 仅管理员可见 | 取决于聚源接入进度 |
| P4 | 许可统一存储 | 无 | 2 个 PR，1 个迁移 |

P0 不改变任何线上行为，可以立即开始，也是后面每一期的前提。

## 5. 不做的事和风险

- 不改判断的冻结输入；`src/lib/industry/types.ts`、`src/lib/facts/types.ts`、`src/lib/judgments/origins.ts` 不动（宏观公式哈希闭包）。
- 不重写已入库的历史数据；B 类换展示源不改任何已有清单哈希。
- 宏观序列的来源是目录版本的一部分，换源即新目录版本，本方案不提供运行时切换。
- 合并客户端时限速参数取各处最保守的值，避免触发供应商限流。
- 路由配置在无服务器环境里要有短缓存和安全回退：读不到配置时用代码默认值。
- 许可约束优先于路由：未获展示许可的来源不能被选为对外展示源。
