# osbornALPHA Auth Email Runbook

## Approved production configuration

| Setting | Value |
|---|---|
| Provider | Resend SMTP |
| Sending domain | `mail.osbornalpha.com` |
| From | `osbornALPHA <login@mail.osbornalpha.com>` |
| SMTP host | `smtp.resend.com` |
| SMTP port | `465` |
| SMTP user | `resend` |
| SMTP password | Resend API key, stored only in Resend/Supabase secrets |
| Project email limit | `30` messages per hour |
| Same-user minimum interval | `60` seconds |
| Email confirmation | Required |
| Click/open tracking | Disabled |

## Provisioning order

1. Create the Resend account and add `mail.osbornalpha.com` as a sending domain.
2. Add the exact SPF, DKIM, and MX records generated by Resend to the DNS provider. Add DMARC after SPF and DKIM verify.
3. Confirm the Resend domain status is `verified` and leave open/click tracking disabled.
4. Create a sending-only Resend API key for Supabase Auth. Do not reuse a marketing-email key.
5. Patch only the required Supabase Auth fields through the Management API:

```json
{
  "external_email_enabled": true,
  "mailer_secure_email_change_enabled": true,
  "mailer_autoconfirm": false,
  "smtp_admin_email": "login@mail.osbornalpha.com",
  "smtp_host": "smtp.resend.com",
  "smtp_port": "465",
  "smtp_user": "resend",
  "smtp_pass": "<RESEND_API_KEY>",
  "smtp_sender_name": "osbornALPHA",
  "smtp_max_frequency": 60,
  "rate_limit_email_sent": 30
}
```

6. Keep `site_url` set to `https://www.osbornalpha.com` and retain both apex and `www` callback URLs. Do not push the local `supabase/config.toml` wholesale to production.

## Rollback

If Resend delivery degrades, disable the custom SMTP fields in Supabase Auth and pause new email signups until a standby provider is configured. Do not disable email confirmation to work around delivery failures.
