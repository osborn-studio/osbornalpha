# G1a i18n 框架+壳层 Implementation Plan

> superpowers:subagent-driven-development or executing-plans。Spec: `docs/superpowers/specs/2026-07-03-g1-i18n-design.md`。

**Goal:** next-intl（无路由模式）+ locale 解析链 + `/en` 公开页前缀（middleware rewrite 方案）+ 语言选择器真接线 + 落地/认证页双语。

**Architecture（关键决策）:** **不引入 `[locale]` 目录段**（避免全站路由迁移）。next-intl 用 "without i18n routing" 模式：`src/i18n/request.ts` 的 `getRequestConfig` 从 **`x-app-locale` 请求头 → `NEXT_LOCALE` cookie → 默认 zh** 解析。`/en` 前缀由 middleware 实现：公开路径命中 `/en(/…)` 时 `NextResponse.rewrite` 到无前缀路径并注入 `x-app-locale: en` 头；应用内不带前缀，纯 cookie。语言选择器写 cookie + upsert user_preferences 双持久化（登录自动恢复留待后续，写入时双写已覆盖主流程）。

**Tech Stack:** next-intl（无路由模式）、既有 middleware 组合、vitest。

```ts
export type AppLocale = 'zh' | 'en';
export const LOCALES: AppLocale[] = ['zh', 'en'];
export const DEFAULT_LOCALE: AppLocale = 'zh';
export function normalizeLocale(raw: string | null | undefined): AppLocale | null
// 'en'/'en-US'/'en-GB'→'en'；'zh'/'zh-CN'/'zh-Hans'→'zh'；'zh-TW'→'zh'（暂并）；其余 null
export function resolveLocale(opts: { header?: string | null; cookie?: string | null; acceptLanguage?: string | null }): AppLocale
// 优先级 header > cookie > acceptLanguage 首个可归一项 > DEFAULT
export function formatDateLocale(iso: string, locale: AppLocale): string   // zh→'zh-CN' en→'en-US' 的 toLocaleDateString
export function formatDateTimeLocale(iso: string, locale: AppLocale): string
```
测试 ≥10：归一化各分支、链优先级、acceptLanguage 解析（'en-US,en;q=0.9,zh;q=0.8' → en；'ja,ko' → zh 默认）、格式化两 locale 输出差异断言。

### T2: next-intl 装配 + middleware + layout

- `npm i next-intl`。`src/i18n/request.ts`：
```ts
import { getRequestConfig } from 'next-intl/server';
import { cookies, headers } from 'next/headers';
import { resolveLocale } from '@/lib/i18n/locale';
export default getRequestConfig(async () => {
  const h = await headers(); const c = await cookies();
  const locale = resolveLocale({ header: h.get('x-app-locale'), cookie: c.get('NEXT_LOCALE')?.value, acceptLanguage: h.get('accept-language') });
  const domains = ['common','landing','auth','errors','settings'];
  const messages = Object.assign({}, ...(await Promise.all(domains.map(async (d) => ({ [d]: (await import(`../../messages/${locale}/${d}.json`)).default })))));
  return { locale, messages };
});
```
- next.config.mjs：`import createNextIntlPlugin from 'next-intl/plugin'; const withNextIntl = createNextIntlPlugin('./src/i18n/request.ts'); export default withNextIntl(nextConfig);`（保留现有 redirects/其他配置）。
- middleware.ts：在 auth gate **之前**加前缀处理（读现文件后最小侵入）：
```ts
// /en 或 /en/<public-path> → rewrite 到去前缀路径 + x-app-locale: en 头
const EN_PREFIX = /^\/en(\/|$)/;
if (EN_PREFIX.test(pathname)) {
  const stripped = pathname.replace(/^\/en/, '') || '/';
  if (isPublic(stripped)) {
    const url = request.nextUrl.clone(); url.pathname = stripped;
    const res = NextResponse.rewrite(url);
    res.headers.set('x-middleware-request-x-app-locale', 'en'); // 传递到 RSC 的正确方式：见下
    ...
  } else { /* /en/<受保护路径> → redirect 到无前缀路径（locale 靠 cookie） */ }
}
```
  **实现注意**：向 RSC 传头的正确姿势是 `NextResponse.rewrite(url, { request: { headers: newHeaders } })`（复制 request headers 后 set('x-app-locale','en')）——实现者按 Next 14 文档核实写法；auth gate 中 `next` 参数必须用 stripped 路径。另外 rewrite 分支也要跑 auth 逻辑（/en 落地页是 public 无妨，保持 isPublic 判断一致）。
- layout.tsx：`const locale = await getLocale();`（next-intl/server）→ `<html lang={locale === 'zh' ? 'zh-CN' : 'en'}>`；body 内 `<NextIntlClientProvider messages={await getMessages()}>` 包 children（读现 layout 保留主题/字体逻辑）。
Gates: tsc + test + build + **手验**：dev 下 curl `/` 与 `/en` 均 200（此时页面仍中文——T4 才抽文案，本任务验证管道通）。
Commit: `feat(i18n): next-intl runtime, /en rewrite middleware, dynamic html lang`
