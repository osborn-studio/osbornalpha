# osbornALPHA Beta Report Completion Design

Date: 2026-07-15
Status: Approved for implementation planning
Owner: osbornALPHA
Execution manager: osstack

## 1. Context

The first beta-report release fixed the exposed AI tool JSON, mobile watchlist layout, naked A-share ticker normalization, quote stale fallback, and a minimum `user_events` pipeline. The remaining report recommendations are the product activation and observability work needed to move users from adding assets to receiving a trustworthy AI insight.

The current production baseline is commit `588ad84`. Its full Vitest baseline passes: 54 test files and 549 tests.

## 2. Goals

1. Help an empty-watchlist user add useful assets without needing to understand the board UI first.
2. Give immediate monitoring value after an asset is added without automatically spending LLM quota.
3. Make asset type and market explicit for stocks, ETFs, convertible bonds, A-shares entered as naked codes, Hong Kong stocks, and US stocks.
4. Persist every Copilot run lifecycle and its sanitized result so product usage can be reviewed.
5. Complete first-party behavioral telemetry with stable session and anonymous identifiers plus server-derived request context.
6. Give administrators a secure `/admin/usage` dashboard for activation, AI conversion, popular assets, failures, and quote-source health.
7. Attribute quote degradation to ticker and source while preserving per-ticker fallback behavior.
8. Reject obvious scanner paths cheaply and exclude them from product analytics.

## 3. Non-goals

- No external analytics vendor is introduced in this release.
- No automatic LLM call occurs when a stock is added.
- No recommendation, rating, or investment advice is generated by the immediate monitoring insight.
- No public or non-admin access to aggregate user analytics is added.
- No attempt is made to automate the report's suggested user interviews.
- No raw tool arguments, tool results, API keys, provider credentials, or unsanitized model text are persisted.

## 4. Product Decisions

### 4.1 Delivery approach

Use the existing Next.js and Supabase stack and deliver vertical slices. This keeps one source of truth for telemetry, avoids a new vendor, and lets each slice be tested and deployed independently.

### 4.2 Post-add feedback

After an asset is added, the watchlist immediately displays a deterministic monitoring insight based on known market, asset type, and quote state. The panel includes a one-click action to start a full Copilot analysis for that ticker. The LLM is called only after the user clicks.

### 4.3 Telemetry vocabulary

`user_events` is the canonical product-behavior table. `usage_events` remains the quota ledger. `ai_runs` is the canonical AI lifecycle and sanitized-result table. These responsibilities stay separate.

## 5. Architecture

The release is split into three vertical slices.

### Slice A: Activation

- Empty-watchlist onboarding with three actions: search and add, batch import, and install a sample watchlist.
- Search responses include a stable `asset_type`.
- Search results show asset type and market, and result selection is tracked.
- A successful add opens a monitoring-insight panel with a direct Copilot action.

### Slice B: AI and telemetry data loop

- `user_events` gains canonical anonymous and request-context fields.
- The browser analytics client maintains a durable anonymous ID and per-tab session ID.
- Copilot creates and updates an `ai_runs` row around the streamed run.
- The Copilot client records start, completion, failure, and copy events.

### Slice C: Operations and reliability

- Quote resolution returns per-ticker source attempts and an aggregate source summary.
- The browser records the source summary on `quote_batch_loaded` and `quote_batch_failed` events.
- An admin-only API aggregates first-party telemetry and AI runs.
- `/admin/usage` renders the operational funnel and reliability metrics.
- Middleware returns a cheap 404 for known scanner paths.

## 6. Data Model

### 6.1 `user_events` additions

Add these backward-compatible columns if absent:

| Column | Type | Purpose |
| --- | --- | --- |
| `anonymous_id` | `text null` | Stable browser identity before or across login boundaries |
| `user_agent` | `text null` | Server-derived, length-limited request context |
| `referrer` | `text null` | Server-derived, origin/path normalized and length-limited |

Keep the existing `metadata jsonb` as the canonical property object. If the production table still has legacy `properties`, migration code preserves it but new application code writes only `metadata`.

Indexes remain focused on `created_at`, `user_id`, and `event_name`; no index is added to user agent or referrer.

### 6.2 `ai_runs`

Create `public.ai_runs` with:

| Column | Type | Notes |
| --- | --- | --- |
| `id` | `uuid` | Primary key, generated by Postgres |
| `user_id` | `uuid not null` | References `auth.users`, delete cascade |
| `ticker` | `text null` | Canonical ticker when the run is asset-specific |
| `method_id` | `text not null` | Resolved Copilot method |
| `question` | `text null` | User question, sanitized and capped at 2,000 characters |
| `status` | `text not null` | `running`, `completed`, or `failed` |
| `content_md` | `text null` | Sanitized final visible analysis only |
| `verdict` | `jsonb null` | Final structured verdict after JSON-safe normalization |
| `error_code` | `text null` | Stable failure category, not a provider secret or stack trace |
| `duration_ms` | `integer null` | End-to-end server run duration |
| `created_at` | `timestamptz` | Start time |
| `completed_at` | `timestamptz null` | Terminal-state time |

RLS permits authenticated users to insert, update, and select only their own rows. Aggregate admin reads use the service-role client only after an authenticated admin-role check.

Indexes cover `(user_id, created_at desc)`, `(status, created_at desc)`, and `(ticker, created_at desc)`.

## 7. API and Event Contracts

### 7.1 Search

`GET /api/search?q=...` keeps its current response and adds `asset_type` to every result.

Allowed values:

- `stock`
- `etf`
- `convertible_bond`
- `fund`
- `index`
- `unknown`

Eastmoney `SecurityTypeName` and `Classify` are the preferred classification inputs. A local deterministic classifier handles mock, Taiwan, fallback, and force-added results. Naked six-digit A-share codes are normalized before classification.

### 7.2 Product events

The browser payload contains `event_name`, `path`, `session_id`, `anonymous_id`, and `metadata`. The server derives `user_id`, `user_agent`, and `referrer`.

New or completed event coverage:

- `watchlist_viewed`
- `watchlist_empty_action_selected`
- `watchlist_sample_installed`
- `stock_search_submitted`
- `stock_search_result_clicked`
- `stock_force_added`
- `watchlist_stock_added`
- `post_add_insight_viewed`
- `post_add_ai_clicked`
- `ai_analysis_started`
- `ai_analysis_completed`
- `ai_analysis_failed`
- `ai_analysis_copied`
- `quote_batch_loaded`
- `quote_batch_failed`

Metadata is capped at 8 KB. Keys associated with secrets are removed recursively. Search-submission events store query length and normalized shape, not the full free-text query. Ticker is allowed because it is core product usage data.

### 7.3 Copilot stream

`POST /api/copilot` creates a running `ai_runs` row after authentication, quota validation, and provider resolution succeed. The SSE stream emits an additive `run` event containing `run_id`; existing clients remain compatible.

At terminal state:

- A successful run updates the row to `completed` with sanitized `content_md`, verdict, duration, and `completed_at`.
- A run that emits or throws an error updates the row to `failed` with a stable error code and any safe partial content.
- Persistence failure is logged as a structured warning but does not break the user stream.

### 7.4 Quote diagnostics

Each source attempt records in memory for the request:

- ticker
- source
- outcome: `success`, `empty`, `timeout`, or `error`
- attempt count
- duration in milliseconds

`/api/quote/batch` adds this under `meta`:

```json
{
  "sources": {
    "eastmoney": { "attempted": 3, "succeeded": 1, "failed": 2, "duration_ms": 4300 }
  },
  "failed_tickers": ["600000.SH"],
  "selected_sources": { "AAPL": "sina" }
}
```

Fresh-cache hits are counted separately as `cache` selections and do not inflate upstream attempts. Stale-cache recovery remains visible through the existing `stale` count.

The client includes the aggregate source summary and failed tickers in the quote event metadata. This creates a queryable denominator without introducing a high-volume diagnostics table.

## 8. User Experience

### 8.1 Empty watchlist

When the total ticker count is zero, replace the passive sentence with an unframed onboarding section containing:

1. A primary search-and-add action that opens the first board's add control.
2. A batch-import action that opens the existing import dialog.
3. A sample-watchlist action that installs one clearly labeled example board with a small cross-market set.

The sample is never installed automatically and never overwrites user data.

### 8.2 Search result labeling

Each result displays name, canonical ticker, market, and localized asset-type text. A force-add fallback also shows the inferred market and asset type before confirmation.

### 8.3 Immediate monitoring insight

After a successful single-stock add, show a compact panel above the watchlist content. It contains:

- asset name and canonical ticker;
- market and asset type;
- quote freshness or a clear unavailable state;
- a neutral monitoring sentence based on quote direction and volatility availability;
- `Run AI analysis`, which navigates to `/copilot?ticker=<ticker>`;
- a dismiss action.

The wording describes what changed and what to monitor. It does not assign a buy/sell rating.

### 8.4 Copilot completion and copy

Copilot shows a copy action only when visible analysis text exists. Copying writes the sanitized visible text and records `ai_analysis_copied` with `run_id`, ticker, and method ID.

## 9. Admin Usage Dashboard

### 9.1 Authorization

Both `/admin/usage` and `/api/admin/usage` require an authenticated user whose `profiles.role` is `admin`. The API performs the role check with the session client, then performs aggregate reads with the service-role client. Non-admin users receive 403; unauthenticated users receive 401 or the normal login redirect for the page.

### 9.2 Filters

The dashboard supports fixed windows of 24 hours, 7 days, and 30 days. The default is 7 days. No arbitrary SQL or free-form date expression is accepted.

### 9.3 Metrics

- Confirmed registrations in the selected window.
- Unique users who viewed a watchlist.
- Unique users who added at least one asset.
- Activation rate: adders divided by confirmed registrations.
- Search submissions, result clicks, force-adds, and add completions.
- AI runs by status, completion rate, median duration, and Copilot method.
- Post-add insight views and AI-click conversion.
- Most-added tickers and their market/asset type when known.
- Quote batches, failed tickers, stale recoveries, and source success/failure counts.
- Recent failed AI runs with safe error code, ticker, method, and time.

Scanner paths, events without recognized product event names, and the admin's own dashboard page views are excluded from funnel calculations.

## 10. Scanner Handling

Middleware returns a plain 404 response before auth/session work for obvious scanner paths, initially:

- `/wp-admin`
- `/wp-login.php`
- `/xmlrpc.php`
- `/.env`
- `/.git`

Prefix matching applies to nested paths. This is load reduction, not a security boundary. Product analytics never emits page-view events for these paths.

## 11. Error Handling and Privacy

- Telemetry and AI-run persistence are best-effort and never block the primary product flow.
- Missing quotes produce an explicit unavailable insight state and retain the Copilot action.
- Interrupted Copilot streams preserve safe partial content and mark the run failed.
- Admin dashboard query failures degrade the affected metric panel and leave other metrics usable.
- Event metadata and AI content pass through recursive secret-key stripping and length limits.
- Raw tool calls and tool results are not stored in `ai_runs` or `user_events`.
- Referrer storage keeps origin and pathname only; query strings and fragments are removed.

## 12. Testing Strategy

### Unit and route tests

- Asset-type classification across A-share stocks, ETFs, convertible bonds, Hong Kong stocks, US stocks, Taiwan stocks, and unknown values.
- Immediate insight generation for positive, negative, flat, stale, and unavailable quotes.
- Analytics identity generation, metadata sanitization, and request-context normalization.
- AI run creation and terminal transitions, including persistence failure.
- Quote source diagnostics for success, retry, empty, timeout, fallback, fresh cache, and stale cache.
- Admin aggregation and 401/403 role boundaries.
- Scanner-path matching without blocking valid product paths.

### Browser verification

Playwright checks mobile and desktop layouts for:

- empty onboarding actions;
- search result type labels;
- sample installation;
- post-add insight panel;
- Copilot ticker handoff;
- no horizontal overflow at 390 px;
- non-admin admin-page denial.

### Release gates

- `npm test`
- `npm run typecheck`
- `npm run build`
- targeted Playwright browser checks
- migration inspection and production schema verification
- production smoke tests for events, search, quote diagnostics, auth redirects, and admin authorization

## 13. Rollout and Recovery

1. Apply additive Supabase migrations first.
2. Verify new columns, `ai_runs`, indexes, and RLS policies.
3. Deploy the application to Vercel using Node.js 22 and an authorized Git author.
4. Verify production public APIs and authentication boundaries.
5. Verify one controlled anonymous event insert and remove or clearly label the smoke event.
6. Verify the admin aggregate endpoint with the owner session when available.
7. Monitor Vercel logs and `user_events` for 30 minutes after deployment.

If application deployment fails, the additive migration is safe to leave in place. If a new UI or API behavior regresses, redeploy the previous known-good application commit; no destructive schema rollback is required.

## 14. Acceptance Criteria

- An empty user can discover all three onboarding paths without opening a hidden board control.
- Search results visibly distinguish supported asset types and canonical tickers.
- Adding an asset displays immediate neutral monitoring value and does not call an LLM automatically.
- The post-add AI action starts Copilot for the correct ticker.
- Every authenticated Copilot run has a terminal `ai_runs` state unless persistence itself is unavailable.
- AI events can be joined to an `ai_runs.id`.
- Admins can inspect activation, AI conversion, popular tickers, failures, and source health for 24-hour, 7-day, and 30-day windows.
- Non-admin users cannot read aggregate analytics or other users' AI runs.
- Quote API responses identify source-level degradation while keeping per-ticker fallback and stale-cache behavior.
- Known scanner paths avoid the application auth and rendering path.
- Unit tests, type checking, production build, browser verification, migration verification, and production smoke tests all pass before osstack moves the release card to `done`.
