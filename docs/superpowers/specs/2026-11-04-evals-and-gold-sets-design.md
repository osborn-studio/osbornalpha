## 1. 目标与非目标

### 1.1 目标

1. **一个黄金集文件契约**（§4）：谁录、何时录、从哪份一手文件的哪一页/行抄的、单位、容差；有版本与锁文件；运行器可校验；录入者不得是被测模块的实现者。
2. **一个运行器、六种评测**（§5）：`official_reconciliation`（我们的值 vs 一手文件）、`dual_source`（来源 A vs 来源 B）、`replay_consistency`（`asOf` 答案 vs 录制快照，跨代码版本）、`reference_regression`（vs ChaosAI 对照样本，只比较不导入）、`extraction_gold`（F3 抽取的字段级 precision/recall，接口）、`judgment_calibration`（F4 结算的 Brier/可靠性，接口）。
3. **两种运行模式**：`ci`（离线夹具，门禁阻断）与 `report`（对生产库，产出 `docs/evals/<date>/` 报告 + `dq_eval_runs` 行）。
4. **两类人工记录有固定格式**：专家抽样记录（§8）、第三方模型审计记录（§9），都能被 `scripts/evals/validate.ts` 校验。
5. **管理员可见**：`/admin/dq` 增加"评测运行"区块（§10），只读。

成功标准（F6 退出条件）：
- `npm run test:db` 包含 `src/lib/evals/evals.integration.test.ts`（critical）；一个故意改错的黄金值使 `official_reconciliation` 返回 `failed=1`（运行器必须能失败）。
- 规格二 §11.4 的六家黄金断言改用本契约文件 `fixtures/gold/facts/plan2.json`，由 `runGoldSet()` 执行，不再各写断言。
- `npx tsx scripts/evals/run.ts --kind official_reconciliation --module facts --mode report` 对生产库跑完后，`docs/evals/<date>/facts-official_reconciliation.json` 与 `.md` 存在，`dq_eval_runs` 多一行，失败项出现在 `/admin/dq` 的"对账失败"列表（经 `dq_reconciliations.eval_run_id`）。
- `replay_consistency` 对 `fixtures/replay/facts.json` 的全部用例给出 `identical | explained_diff | unexplained_diff` 三态之一；`unexplained_diff > 0` 时退出码非零。
- `reference_regression` 永远不写 `financial_facts`、`macro_observations` 或任何展示表（集成测试断言表行数不变）。

### 1.2 本规格之外

- 黄金值本身的录入（30 家 × 4 期 × 6 科目由计划三交付；6 家由规格二交付；抽取黄金集 30 篇由 F3 交付）。本规格只定义契约与运行器，并把规格二的 6 家作为首个实例。
- 计划三的跨来源对账**生产者**（`src/lib/dq/reconcile.ts`，在采集路径里隔离超差行）。本规格提供它要复用的比较原语（§5.2），不替它写隔离逻辑。
- 判断层的结算引擎与预测登记（F4）。
- LLM 备忘录评测（已有 `research_eval_cases/runs`，另一用途，见 §2）。
- 任何面向公众的页面。

## 3. 术语与评测种类

| `kind` | 问题 | 左值 | 右值 | 真值地位 |
|---|---|---|---|---|
| `official_reconciliation` | 我们存的/算的数等于一手文件上印的数吗 | 系统值（读接口或表） | 黄金集（人从一手文件抄录） | 右值是真值 |
| `dual_source` | 两个独立来源对同一键一致吗 | 来源 A 的系统值 | 来源 B 的系统值 | 都不是真值；不一致 = 待查 |
| `replay_consistency` | 同一 `asOf` 问题，今天的答案和当初录制的一样吗 | 当前代码对录制请求的答案 | 录制快照 | 差异必须被解释（数据迟到 / 隔离处理 / 公式升级 / 代码缺陷） |
| `reference_regression` | 我们的数和对方页面显示的差多少、为什么 | 系统值 | ChaosAI 公开页面抓取值 | 右值**不是**真值；只要求差异可解释 |
| `extraction_gold` | 抽取器字段级 precision/recall | 抽取器输出 | 人工标注（F3） | 右值是真值 |
| `judgment_calibration` | 登记过的概率校准如何 | 预测 | 结算结果（F4） | 事实结算是真值 |

一次**运行**（run）= 一个 `kind` × 一个 `module` × 一个黄金集/样本集版本 × 一个 `code_version` × 一个 `mode`；产出若干**案例结果**（case result），每条有 `outcome ∈ {pass, fail, missing, unit_mismatch, explained_diff, unexplained_diff, skipped}` 与 `detail`。

`module` 当前取值：`facts`（规格二）、`metrics`（规格二派生）、`macro`（宏观工作台）、`industry`、`company`、`foreign_research`（后三者规格待立）。

## 4. 黄金集文件契约

### 4.1 路径与版本

```
fixtures/
  gold/
    lock.json                       # {files:[{path, sha256, version}]}，改黄金集必须同时改锁
    recorders.json                  # 允许录入的人：[{id, role, modules:[…], added_at, added_by}]
    facts/plan2.json                # 规格二 §11.4 的 6 家（首个实例）
    facts/plan3-30.json             # 计划三 30 家（待录）
    macro/<set>.json
    <module>/<set>.json
  replay/<module>.json              # §5.3 录制快照
  replay/explanations.json          # §5.3 差异解释账本
  reference/chaosai/<page>.json     # §5.4 对照样本（只读、只比较）
  reference/chaosai/explanations.json
```

一个黄金集文件 = 一个 JSON 对象：

```jsonc
{
  "schema_version": 1,
  "set_id": "facts/plan2",
  "version": 3,                       // 每次改动任何 case 的 value/unit/source 必须 +1
  "module": "facts",
  "module_implementers": ["<recorder id>", …],   // 这些人不得作为 recorded_by
  "default_tolerance": {"type": "rel", "value": "0"},
  "history": [{"version": 2, "changed_at": "…", "changed_by": "<id>", "reason": "…", "cases": ["…"]}],
  "cases": [ … ]                      // §4.2
}
```

### 4.2 案例（case）

```jsonc
{
  "case_id": "AAPL/revenue/2023-09-30/12M",          // 文件内唯一；稳定；不含 issuer_id（uuid 因环境而异）
  "subject": {"market": "US", "cik": "320193"},     // 或 {"market":"A","ts_code":"600519.SH"}；macro 用 {"series_id": "US_CPI"}
  "target": {"concept": "revenue", "period_start": "2022-10-01", "period_end": "2023-09-30", "consolidation": "consolidated"},
  "unit": {"currency": "USD", "scale": 1},           // 一手文件印的单位；scale ∈ {1, 1e3, 1e6, 1e9}
  "value": "383285000000",                           // 十进制字符串；不用 JSON number
  "tolerance": {"type": "rel", "value": "0"},        // 缺省用文件级 default_tolerance；type ∈ abs|rel
  "source": {
    "document_type": "10-K",                         // 10-K | 10-Q | 20-F | 年报 | 半年报 | 季报 | 更正公告 | 指数公司日度估值 | 统计局月报 …
    "document_id": "0000320193-23-000106",           // accession / 巨潮 announcementId / 文件 sha256
    "url": "https://www.sec.gov/Archives/edgar/data/320193/000032019323000106/…",
    "available_date": "2023-11-03",
    "locator": {"page": 28, "table": "CONSOLIDATED STATEMENTS OF OPERATIONS", "row": "Total net sales", "column": "2023", "as_printed": "383,285"}
  },
  "provenance_kind": "transcribed",                   // transcribed | synthetic（仅限测试夹具，report 模式拒绝）
  "recorded_by": "<recorder id>", "recorded_at": "2026-11-10T03:00:00Z",
  "reviewed_by": "<recorder id>", "reviewed_at": "…",   // 可选；计划三 30 家要求必填（§12）
  "expect": "present",                                // present | missing（文件上没有这个值，用来测试"缺失保持缺失"）
  "notes": ""
}
```

规则（由 `src/lib/evals/gold.ts::validateGoldSet()` 执行，CI 单测对每个提交的黄金文件跑一遍）：
- `value` 必须是 `^-?\d+(\.\d+)?$`；`as_printed` 必填，去掉千分位与括号后必须与 `value / scale` 相等（抄录自检）。
- `source.locator` 至少有 `page` 或 `row` 之一，`as_printed` 必填；`document_id` 与 `url` 必填（内部文件用 `sha256:<hex>` 作 `document_id`，`url` 可为 `private://<bucket>/<path>`）。
- `recorded_by` ∈ `recorders.json` 且其 `modules` 含本 `module`；`recorded_by ∉ module_implementers`。
- `expect='missing'` 的 case 没有 `value`，但有 `source`（说明看过哪份文件）。
- `provenance_kind='synthetic'` 的文件只能放在 `src/**/fixtures/`，不能放在 `fixtures/gold/`。
- `lock.json` 里的 sha256 与 `version` 必须匹配；不匹配 → `gold_lock_mismatch`，所有依赖该集的评测拒绝运行。

### 4.3 谁可以改

- 改 `fixtures/gold/**` 的 PR 必须同时改 `lock.json`，并由 `recorders.json` 中的一人以外的另一人审核（CODEOWNERS 不在本仓库使用，由 PR 审核规则执行；owner 决策 §15 D2）。
- 实现者可以**新增**夹具数据（录制的 API 响应放 `fixtures/edgar/`、`fixtures/tushare/`，规格二 §11.1）但不能新增或修改黄金值。
- 删除 case 不允许；撤回用 `"retracted": {"at", "by", "reason"}`，运行器计 `skipped`。

### 4.4 硬规则

- 运行器任何路径都不生成、不推断、不"修正"黄金值；黄金值只能来自人读一手文件。
- 黄金值一律用文件印的单位与精度；运行器做 `scale` 换算，不做币种换算（币种不同 → `unit_mismatch`，不是 fail 也不是 pass）。
- 黄金集 subject 不含 `issuer_id`；运行时 `resolveIssuer(client, {cik} | {ticker: ts_code}, {today})`，解析失败 → `missing(subject_unresolved)`。

## 5. 评测种类的定义

公共：`src/lib/evals/types.ts` 定义 `EvalKind`、`CaseResult`、`RunSummary`；每种 kind 是 `src/lib/evals/kinds/<kind>.ts` 里的一个纯函数 `run(deps, config) => Promise<{cases: CaseResult[]; summary: RunSummary}>`，`deps` 含读适配器（§5.6）、时钟、`code_version`。

### 5.1 `official_reconciliation`

输入：黄金集 + 模块读适配器。对每个 case：
1. 解析 subject → `issuer_id`（或 `series_id`）。
2. 读系统值：facts 用规格二 `FactsDb.factsOfIssuer(issuer,{concepts:[concept], periodEndGte/Lte})` 取与 `target` 完全匹配（`period_start/period_end/consolidation`）的当前可见行；metrics 用 `metricsOfIssuer`；macro 用 `macro_observations` 的 `status='ok'` 最新 vintage。
3. 单位：系统行 `unit` 的币种 ≠ 黄金币种 → `unit_mismatch`；scale 换算后用 §5.2 比较。
4. 结果：`pass`；`fail`（带 `left_value,right_value,abs_diff,rel_diff,tolerance`）；`missing`（系统无该值；若 case `expect='missing'` 则为 `pass`，反之系统**有**值而 case 期望 missing → `fail(unexpected_value)`）。

门槛（`ci` 模式）：`fail=0`、`unit_mismatch=0`、`missing=0`（夹具保证存在）。`report` 模式：`fail=0` 才算通过；`missing` 单列，不计入失败率但报告里列出（缺失是覆盖问题，不是正确性问题）。

### 5.2 比较原语 `src/lib/evals/compare.ts`

```ts
export function compareDecimal(left: string, right: string, tol: {type:'abs'|'rel'; value:string}):
  {passed: boolean; absDiff: string; relDiff: string|null}
```
- 十进制字符串按小数位对齐后转 `BigInt` 比较，无浮点；`rel`：`|l−r| ≤ tol × max(|l|,|r|,1)`（与 `dq_reconciliations.tolerance` 列注释同义）；`relDiff = |l−r| / max(|l|,|r|,1)`，分母为 0 时按 1。
- 这是计划三 `reconcile.ts` 必须复用的同一函数（依赖接口 §11.2），保证"评测说过"与"采集时隔离"用同一尺子。

### 5.3 `replay_consistency`

录制：`scripts/evals/record-replay.ts --module facts --request '/api/facts/AAPL?concepts=revenue&durations=12M&asOf=2024-06-30'` 对**生产**公开读接口发请求，写入 `fixtures/replay/facts.json`：

```jsonc
{"case_id": "facts/AAPL/revenue/asOf=2024-06-30", "request": {"path": "/api/facts/AAPL", "query": {"concepts":"revenue","durations":"12M","asOf":"2024-06-30"}},
 "recorded_at": "…", "code_version": "<40 hex>", "mapping_gen": 3, "formula_version": "v1",
 "expected": {"hash": "<sha256 of canonical json>", "payload": {…}}}
```

- 只录带 `asOf` 且 `asOf` 早于录制日的请求（历史答案才有"应当不变"的含义）。
- 规范化：剔除响应里的 `mappingGen`（顶层）、缓存头、`factId`（uuid 因重建而异）；键排序；值保持字符串（读接口已用 `value_text`）；sha256。
- 比较：当前代码对同一请求再算一次（`ci` 模式用内存/本地 DB 的夹具；`report` 模式打生产读接口），逐字段 diff。
- 三态：`identical`；`explained_diff`：差异的每个字段都能在 `fixtures/replay/explanations.json` 找到一条 `{case_id, field, reason_code, evidence, added_by, added_at}`，`reason_code ∈ {late_filing, quarantine_resolved, mapping_gen_upgrade, formula_version_change, ticker_reassignment, bug_fixed}`，`bug_fixed` 必须给 PR 号；`unexplained_diff`：其余。
- 自动归因提示（不替代账本）：`report` 模式下运行器查 `financial_facts.created_at > recorded_at`（同 issuer、concept）与 `dq_quarantine.resolved_at > recorded_at`，在 `detail.hints` 里给出"可能是数据迟到/隔离处理"，人确认后才写账本。
- 门槛：`unexplained_diff = 0`。跨代码版本：录制的 `code_version` 与当前不同是常态，不是差异原因；`code_version` 相同却出现差异 → 直接 `unexplained_diff(data_changed_same_code)`。

宏观模块的回放对象是 `macro_snapshots(snapshot_id)` + `macro_regime_results`（宏观规格 §4.3）：请求是 `/api/macro/overview?snapshot=<id>`；比较 `scores/contributions/primary_state`。接口待宏观实现时对齐（§11.4）。

### 5.4 `reference_regression`（ChaosAI 对照样本）

边界（硬规则）：
- 样本来自对方**公开页面**的抓取，文件 `fixtures/reference/chaosai/<page>.json` 每条记录带 `captured_at`、`page_url`、`page_sha256`（取自 `EVIDENCE.json`）、`as_displayed`（页面原文）、`parsed_value`、`parsed_unit`、`their_declared_source`（页面标注的来源，如"申万指数周频 xlsx"）。
- 这些文件**只被 `reference_regression` 读取**；运行器以类型系统保证（`ReferenceSample` 类型不可赋给任何写适配器的输入类型），集成测试断言运行前后 `financial_facts`、`financial_metrics`、`macro_observations`、`macro_snapshots` 行数不变。
- 不进 `dq_reconciliations`（那张表的语义是"两个我们认可的来源"）；结果只在报告文件与 `dq_eval_runs.summary`。
- 页面与 UI 任何地方不得展示 `reference` 值；报告 `.md` 可以列。

比较：按 case 的 `tolerance`（文件级缺省 `rel 0.01`，取总纲 §1.3 "自算值与官方发布值偏差 < 1%"的同一尺度；owner 可改 §15 D1）；超差的 case 必须在 `fixtures/reference/chaosai/explanations.json` 有 `reason_code ∈ {membership_pointintime, aggregation_method, restatement, unit_or_basis, their_placeholder, their_proxy, unknown}`；`their_placeholder/their_proxy` 对应总纲 §1.1 指出的"估值维度 50 占位、现金流用利润增速代理"。

门槛：`ci` 模式不跑（样本不是真值，不应阻断提交）；`report` 模式作为板块上线门槛：`unexplained (reason_code=unknown) = 0`。

### 5.5 `dual_source`

输入：一对来源的键集合（配置 `src/lib/evals/pairs.ts`：`{pair_id, module, left_source, right_source, key_selector, tolerance}`），例如 `facts:edgar-companyfacts vs facts:10k-text-extraction`（计划三）、`facts:tushare vs facts:akshare`（计划三）、`macro:fred vs macro:official-release`（宏观）。运行器对每个键读两边当前值，`compareDecimal`，容差缺省 `rel 0.005`（规格一 §5.2）。

- 结果：`pass | fail | missing(left|right)`。
- 门槛：`pass / (pass+fail) ≥ 0.95`（规格一 §9 "对账通过率 ≥ 95%"），且 `fail` 全部出现在 `dq_reconciliations`。
- 与计划三的分工：计划三 `reconcile.ts` 在采集路径逐行比较并隔离；本 kind 是**事后全量复核**（同一 `compareDecimal`、同一容差），用于报告与趋势，不隔离。

### 5.6 读适配器 `src/lib/evals/adapters/<module>.ts`

```ts

  resolveSubject(subject: GoldSubject, today: string): Promise<{id: string} | null>;
  readValue(id: string, target: GoldTarget, opts: {asOf?: string}): Promise<{value: string; unit: {currency?: string; scale: number}; ref: Record<string, unknown>} | null>;
```

### 6.1 决定

| 内容 | 放哪 | 理由 |
|---|---|---|
| 黄金集、回放快照、对照样本、解释账本 | 仓库文件（`fixtures/`） | 版本化、可审、PR 审核即访问控制；与代码同一提交 |

| 运行摘要 | 表 `dq_eval_runs` | 管理页要按时间看趋势；文件不能被页面查询 |
| 逐案失败（`official_reconciliation`、`dual_source`） | `dq_reconciliations` 新增两列 `eval_run_id`、`case_id` | 该表就是为"左值 vs 右值 + 容差 + passed"设计的，`/admin/dq` 已展示失败列表，不另建 |
| `replay_consistency` / `reference_regression` 逐案 | 只在报告文件；摘要进 `dq_eval_runs.summary` | 对照样本不得入对账表（§5.4）；回放差异需要人工解释，账本在文件 |

不新建 `eval_results` 表：逐案数据有两张已存在的归宿（对账表、报告文件），第三处会产生三份真相。

### 6.2 迁移 `supabase/migrations/20261106120000_dq_eval_runs.sql`（时间戳在实施日重分配，必须晚于规格二的 `20261106090000`）

```sql

  run_id        uuid primary key,
  kind          text not null check (kind in ('official_reconciliation','dual_source','replay_consistency','reference_regression','extraction_gold','judgment_calibration')),
  module        text not null check (length(module) between 1 and 32),
  mode          text not null check (mode in ('ci','report')),
  set_id        text not null,                     -- 'facts/plan2' / 'replay/facts' / 'reference/chaosai/industries' / pair_id
  set_version   integer not null check (set_version >= 1),
  set_sha256    text not null check (set_sha256 ~ '^[0-9a-f]{64}$'),
  code_version  text not null check (code_version ~ '^[0-9a-f]{40}(-dirty)?$'),
  started_at    timestamptz not null,
  finished_at   timestamptz,

  summary       jsonb not null default '{}',       -- {pass,fail,missing,unit_mismatch,explained_diff,unexplained_diff,skipped,total,thresholds:{…},gate:'pass'|'fail'}
  report_ref    text,                              -- 'docs/evals/2026-11-20/facts-official_reconciliation.json' 或 'reports/evals/<run_id>.json'
  triggered_by  text not null check (triggered_by in ('cron','manual','script','ci')),
  constraint dq_eval_runs_summary_object check (jsonb_typeof(summary) = 'object'),
  constraint dq_eval_runs_finished_after_started check (finished_at is null or finished_at >= started_at),
  constraint dq_eval_runs_running_iff_unfinished check ((status = 'running') = (finished_at is null))
);
create index if not exists dq_eval_runs_module_kind_idx on public.dq_eval_runs(module, kind, started_at desc);

alter table public.dq_reconciliations
  add column if not exists eval_run_id uuid references public.dq_eval_runs(run_id) on delete set null,
  add column if not exists case_id text;
create index if not exists dq_reconciliations_eval_run_idx on public.dq_reconciliations(eval_run_id) where eval_run_id is not null;

alter table public.dq_eval_runs enable row level security;
revoke all on public.dq_eval_runs from public, anon, authenticated;
grant select, insert, update, delete on public.dq_eval_runs to service_role;
```

- `dq_reconciliations` 现有列注释与约束不变；评测写入时 `batch_id` 为 null、`eval_run_id` 非空；计划三的采集路径写入时反之。两者都为空的行视为无效（检查约束 `dq_reconciliations_origin check (batch_id is not null or eval_run_id is not null)`，`not valid` 后再 `validate`，因为表现在为空所以可直接 valid）。
- `database.types.ts` 手工补 `DqEvalRun` 与 `DqReconciliation` 的两列；`migrations.lock.json` 追加。
- 存储层 `src/lib/evals/store.ts`：`startRun/finishRun`（形态同 `startBatch/finishBatch`，`status='running' iff finished_at is null`）、`writeReconciliations(rows)`（分块 ≤ 500 行，经 `TableClient.insert` 逐行；一次 run 的失败行以 100 条为上限写库，其余只在报告文件，`summary.reconciliations_truncated=true`）。

### 6.3 `code_version`

运行器取 `process.env.VERCEL_GIT_COMMIT_SHA`；本机脚本取 `git rev-parse HEAD`，工作树不干净时追加 `-dirty`；测试用固定 40 个 `a`。缺失 → 拒绝运行（与规格二 `code_version` 缺失拒绝一致）。`report` 模式拒绝 `-dirty`。

## 7. 运行器与触发

### 7.1 CLI `scripts/evals/run.ts`

```
npx tsx scripts/evals/run.ts --kind <kind> --module <module> [--set <path>] [--pair <pair_id>]
    --mode ci|report [--out docs/evals/<date>] [--write-db] [--limit N] [--case <case_id>]
```

- `ci`：读 `fixtures/`，适配器用传入的本地 DB（`S4_TEST_STATE`）或内存实现；不打网络；不写 `dq_eval_runs`；写 `reports/evals/<run_id>.json`；门槛不过 → 退出码 1。

### 7.2 报告格式

`<module>-<kind>.json`：

```jsonc
{"run_id":"…","kind":"…","module":"…","mode":"report","set":{"id":"facts/plan2","version":3,"sha256":"…"},
```

## 12. 测试策略

### 12.1 单元（vitest，`src/lib/evals/*.test.ts`）

- `compare.test.ts`：整数、长小数（20 位）、负数、`abs/rel`、分母 0 用 1、`relDiff` 精度；属性测试（种子随机 200 次）：`compareDecimal(a,a)` 恒 pass；`rel` 单调（容差放大不会从 pass 变 fail）。
- `gold.test.ts`：`validateGoldSet` 对每条规则各一条反例（缺 `as_printed`、`as_printed` 与 `value/scale` 不符、`recorded_by` 是实现者、`synthetic` 放错目录、锁不匹配、删除 case）；对 `fixtures/gold/**` 全部文件跑通过。
- `kinds/official.test.ts`：内存适配器；pass/fail/missing/unit_mismatch/`expect=missing` 五种 outcome；**变异测试**：把黄金值 +1 后必须 fail。

- `kinds/reference.test.ts`：类型层面不可写（编译期）+ 运行时写适配器收到 `ReferenceSample` 抛错；`unknown` 解释计 unexplained。

## 13. 错误处理

| 情形 | 行为 | 码 | 运行状态 |
|---|---|---|---|
| 黄金文件不合契约 / 锁不匹配 | 不运行 | `gold_invalid` / `gold_lock_mismatch` | 不建 run（退出码 2） |
| `code_version` 缺失或 `report` 模式下 `-dirty` | 不运行 | `code_version_missing` / `dirty_tree` | 不建 run |
| subject 解析失败 | 该案例 `missing(subject_unresolved)` | — | 继续 |
| 读适配器错误（网络 / 5xx） | 重试 3 次退避；仍失败 → 该案例 `skipped(read_error)`，计入 `summary.read_errors` | `read_error` | `read_errors > 0` → 门槛判 `fail`，`status='failed'` |
| 回放请求返回非 200 | `unexplained_diff(http_<status>)` | — | 继续 |
| `report` 模式写 `dq_eval_runs` 失败 | 报告文件仍写；退出码 1 | `store_write_failed` | `status` 留 `running`（人工收尾；页面标"异常") |
| cron 超时将至 | 不开始新集；已完成的集正常收尾 | `deadline_hit` | 已跑集按各自结果 |
| `synthetic` 集在 `report` 模式 | 拒绝 | `synthetic_in_report` | 不建 run |
| 对照样本被传给写适配器 | 抛错，进程退出 | `reference_write_attempt` | `error` |
