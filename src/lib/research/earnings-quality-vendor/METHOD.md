# Earnings quality candidate — acceptance contract

This is an additive candidate component, not a claim that the 29 financial
workflows or the existing v0.1.1 report wrapper have passed financial-quality GA.
The existing workflow identity stays stable; the component has its own version.

## Scope

One zero-dependency, no-network JavaScript module is canonical in this skill.
Model and Alpha consume byte-identical, digest-pinned copies. It takes explicitly
sourced monetary facts and compares two full-year periods. It calculates cash
conversion, net margin, cash less capex (NOT FCFF), reported changes and prewritten
numeric Thesis conditions. Qualitative Thesis stays unassessed. It neither
recommends trades nor proves economic causality or investment quality.

SEC Companyfacts import is deliberately narrow: one issuer, US-GAAP, USD,
explicit accession and exact start/end dates. No choosing a later filing, mixing
taxonomies, converting YTD to quarters, or silently picking conflicting facts.
Other statements need a reviewed fact packet; arbitrary PDF extraction is absent.

## Acceptance

- CFO 18 and net income 12 always yields 1.5 and “greater”, never “less”.
- Non-positive denominators, metadata conflicts, missing sources and estimates
  cannot produce an apparently verified ratio. No default-to-zero.
- Currency, unit, accounting basis, issuer, and duration must match. Annual
  52/53-week differences remain explicitly flagged, not calendar-normalized.
- Every calculation includes operand IDs and its formula; IDs resolve to a
  source and stable locator. The source text itself is not authenticated by an ID.
- Cutoff and filing dates prevent look-ahead. Thesis written after the current
  period starts is not accepted as a pre-existing condition.
- State transitions mean only numeric conditions met/breached, never Thesis proven.
- Golden facts/answers are independently checked, not generated by the evaluator.
- UI reports engine/data scope, failure cases and unrun model benchmarks separately.
- No live LLM A/B score until identical inputs, model, tools, token budgets and
  actual retained outputs are available. Kernel tests are not an LLM benchmark.

## Community methods consulted (2026-09-07)

- [Anthropic: agent evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents): outcome assertions, regression cases, calibrated human review.
- [Promptfoo: factuality](https://www.promptfoo.dev/docs/guides/factuality-eval/): fixed reference answers; never substitute uncalibrated self-judgment.
- [FinanceBench](https://github.com/patronus-ai/financebench): financial questions tied to evidence. No dataset or vendor skill text copied.
- [SEC XBRL API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces): units and fiscal-date contexts must be kept explicit.

This is original OSBORN implementation. Reviewers must distinguish a frozen
synthetic regression, manually transcribed public facts and a live extraction run.
